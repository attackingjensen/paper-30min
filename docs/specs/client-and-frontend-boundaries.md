# 正式客户端与前端边界规格

来源： [Wayfinder：正式客户端与前端重设计的规格边界](https://github.com/attackingjensen/paper-30min/issues/22)

## 客户端入口

- Windows 使用 Tauri 桌面应用作为正式入口，保留浏览器阅读器用于迁移、回退和本地书库导入。
- Android 是移动阅读伴侣，首版只消费移动书架中已同步的移动阅读副本。
- Android 不提供导入、模型调用、精读生成、编辑或完整书库管理。

## 前端重设计

允许调整导航、信息架构、布局、按钮、背景和视觉表现。论文导入、精读、PDF、问答、翻译、回想卡片、书库和同步等业务行为、需求边界及数据契约保持一致。

## 本地与客户端能力边界

Windows 本地书库是论文内容、PDF、精读结果、翻译、回想卡片和论文问答的权威来源。JavaScript 负责领域流程编排；Rust 提供窄接口，按五组能力分层：书库与迁移、文件与 PDF、网络与云端同步、模型调用、任务与生命周期。接口需版本化、可测试，不在 Rust 复制论文领域规则。

## Android 缓存与同步

Android 缓存移动阅读副本和阅读位置，已缓存内容可离线阅读。网络恢复后自动重试内容同步、阅读位置同步和删除队列。Android 不接收 API Key、应用设置、完整本地书库或未加入移动书架的论文。

## 任务反馈与关闭

生成、下载、内容同步和删除统一呈现等待、进行中、成功、失败、已取消、待重试状态，同时保留各自取消和恢复语义。Windows 和 Android 提供可从主导航进入的任务/同步状态视图，论文详情提供单篇任务上下文。关闭 Windows 时，对仍在运行的任务提供等待完成或停止任务的选择；停止遵循任务可恢复的取消语义。

## 迁移与交付

保持现有书库、整库 JSON 导出、技能文件和同步数据格式兼容。Windows 交付普通安装包，Android 交付签名 APK；两端支持手动覆盖升级并保留数据。旧浏览器书库通过整库导出文件迁入，API Key 在客户端重新配置。
