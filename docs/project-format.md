# 本地工程文件契约

本契约对应 v2 的 S1/S2/S3 与 STE-69、STE-76、STE-79、STE-81、STE-82。工程围绕创建时的论文，正文以普通文件为权威，首版不使用 SQLite，也不自动初始化 Git。

## 文件组织

```text
工程文件夹/
  paper30min.json       # 轻量清单，formatVersion = 1
  .paper30min-citations.json # 正式引用字典，须随工程保留
  text/paper.pdf        # 创建时复制的工程论文
  text/<batchId>/paper.md # 独立解析批次的完整正文，尚待 Agent 审阅
  text/<batchId>/images/ # 正文图片
  .paper30min/parsing/<batchId>/ # 解析原始返回、恢复状态与块映射
  map/                 # 阅读地图
  explanations/        # 按顺序组织的论文精解
  notes/               # 笔记与用户文档
  memories/            # 用户按需生成的可编辑记忆卡片
  tmp/                 # 临时脚本与产物
  .pi/sessions/        # Pi 原生 JSONL 会话
```

允许增加普通文件和目录，文件树直接从磁盘读取，不要求逐个登记。内部隐藏目录、隐藏临时文件与 `node_modules` 不展示。应用持续监听当前工程，文件树自动更新；也可手动刷新，窗口重新获得焦点时刷新。Markdown 支持阅读、CodeMirror 源码编辑和分屏预览，笔记入口可新建 `.md` 文件。

清单字段：

| 字段 | 含义 |
| --- | --- |
| `formatVersion` | 工程格式版本，目前只接受 `1` |
| `id`、`name` | 工程身份与名称 |
| `paper` | 固定工程论文的 `id`、相对 `path`、原文件 `sha256` |
| `materials` | 参考材料身份与相对路径，使用同一记录格式 |
| `map` | 地图相对路径，未生成时为 `null` |
| `explanations` | 按阅读顺序排列的精解相对路径 |
| `translations` | 目标语言到全文译文相对路径的映射 |

相对路径使用 `/`，不允许父级穿越、绝对路径、Windows 保留名称或指向工程外的符号链接。文档身份在应用内改名／移动后保持不变，相关清单字段随路径更新。引用复用文档身份和版本，不将路径作为身份。

普通新增文件不一定具有已登记的文档身份。工程论文与参考材料必须有独立身份和路径；不能把参考材料设为工程论文，也不能通过材料移出入口删除工程论文。

文档记录可选的 `annotationSha256` 保存应用内批注写入后的最新字节版本，原始 `sha256` 不变。只有保存基线等于原始版本或上次已记录的批注版本时才推进此值；从外部修改版本继续保存不能恢复原解析的有效性。解析开始、处理中、恢复和审阅均接受这条保存链上的当前版本，外部修改仍明确失效；`readPdf` 在同一次工程队列操作中返回字节、哈希和可选的已登记文档快照，避免并发保存使清单与字节版本错配。引用定位继续按文档身份、页码／尺寸／区域或批注 ID 核验。PDF 保存仍以当前读取版本执行冲突检查。

## 创建、失败与搬迁

创建前展示名称和完整工程路径，用户可修改名称和本次保存位置。保存位置必须已存在且可写，同名子目录不覆盖。新目录由独占创建取得；PDF 复制到 `text/paper.pdf`，再计算 SHA-256 和写入清单。复制、初始化和本机最近工程登记均成功后才返回成功。

复制或初始化失败、用户取消、正常退出应用时取消未完成的创建，清理本次拥有的目录，不登记成功工程。登记开始后是提交点，迟到的取消不撤回已提交工程。强制杀进程或断电不保证清理未完成目录；没有成功登记的目录需要用户检查，不自动删除。

外部 PDF 保持不变，其原路径不写入工程清单。后续使用工程内副本；整体复制或移动工程后，可从任意位置重开。搬迁不携带机器配置；PDF 阅读位置及 Markdown 视图、位置保存在工程内 `.paper30min-reading.json`，Pi 原生会话保存在 `.pi/sessions/`。PDF 页码、滚动、缩放与布局按工程内路径恢复，不再保存或比较位置记录中的 PDF 哈希；旧记录中多余的 `sha256` 字段仍可读取，但不参与恢复判断。

材料添加先完整复制，再登记身份。改名／移动只操作文件，目标父目录须已存在且目标不能覆盖；清单保存失败时尝试回到原路径。文件移动依赖本地文件系统硬链接提供不覆盖保证，跨卷挂载点不支持，应通过添加材料复制。

外部改名／移动后，缺失文件显示重新关联。关联文件必须匹配原始 `sha256` 或最新已登记的 `annotationSha256`，不能将另一篇论文冒充固定工程论文；工程外的匹配文件会复制进工程，工程内的匹配文件更新相对路径。引用跳转不再以全文件哈希一致为前提；正文替换或插删页后可能定位错误。

移出参考材料通过系统回收站执行，确认提示相关引用失效，研究成果保留。回收站失败时不移除清单记录；文件已移入回收站而清单保存失败时，明确提示从回收站恢复再刷新。

## 旧 PDF 批量导入

设置默认工程文件夹后，可从启动页或「设置 → 工程文件夹」进入「导入旧 PDF」，选择旧桌面书库根目录。Windows 选择器默认指向 `%APPDATA%/com.paper30min.reader`。只枚举 `attachments/<论文 ID>/pdf`，不读取旧 SQLite，也不读取笔记、回忆卡、其他附件、解析缓存或成果。旧版磁盘文件统一名为 `pdf`，因此默认工程名为 `pdf-<论文 ID>`，导入前可修改。同名目录自动追加 ` (2)` 等序号，独占创建保证不覆盖。

导入逐份复用普通工程创建：将原始 PDF 复制到 `text/paper.pdf`，核验复制前后的 SHA-256，再登记最近工程；一份失败不阻止其他项。源文件及其父路径不得包含符号链接或目录联接，默认工程文件夹不得位于旧书库内。停止或正常退出取消当前项，已成功工程保留，失败和未完成项可重试。强制终止后未完成目录仍保留，不自动删除，重试会避开该目录。

本机配置目录的 `legacy-imports.json` 保存导入来源路径、PDF 哈希、预定工程目录及工程身份；不放进工程、不随工程搬迁，也不保存旧内容。创建前原子保存记录，重试时核验工程身份和实际 PDF 内容；目标 PDF 为原始版本或最新已登记的批注版本时均复用原工程，完整工程若尚未登记则补登记，成功项不重复创建。来源路径改变、源 PDF 内容改变或目标工程已被移走时不承诺跨路径去重。该文件损坏时明确报错，不清空记录后盲目重导。

导入不自动打开 Agent、解析、审阅、建图或生成，也不要求模型配置。旧书库及原文件保持原样，不提供旧数据备份恢复或旧成果重建。原往返导入测试 #139 中仍适用的 PDF 复制完整性、失败清理和幂等重试由新版 Electron 测试覆盖；旧库往返、附件归属与备份恢复已退出新版范围，不据此关闭旧 Issue。

## PDF 引用

Markdown 使用 `[描述](paper://cite/<id>)`，`id` 为去掉连字符的随机 UUID（32 位小写十六进制）。链接不包含机器路径或可编辑坐标，重复使用同一链接不创建新引用。`.paper30min-citations.json` 是正式工程数据，不是阅读位置缓存；丢失它会使链接失效，搬迁和备份必须包含该文件。无需数据库。

字典结构为 `{ formatVersion: 1, projectId, citations: { [id]: Citation } }`。每个引用保存 `id`、`documentId`、`kind`、`text` 和 `pages`，不再持久化 PDF 全文件哈希；旧记录中的 `sha256` 读取时忽略。`kind` 为 `text`、`region` 或 `page`；`text` 保存实际选中文字，不从附近段落推测。每页保存 `page`、`width`、`height` 和 `rects`；矩形为 `{ origin: { x, y }, size: { width, height } }`。图片不嵌入 JSON。`read_pdf` 每次读取当前 PDF 并独立渲染整页 PNG，不接受区域坐标或预期哈希参数，将图像、路径、文档身份、文件版本、页码、总页数、顶层 `width` / `height`（PDF 点单位）、实际缩放与来源信息保存在 Pi 工具结果中；不创建或返回引用，不改动此字典或历史引用，不提取或返回文本层，也不执行 OCR 或短句匹配。Agent 可继续复用解析稿中实际对应来源的已有块链接；无可用引用时说明文件路径、页码与引用缺失，转录校对仍可保存已核实的正文纠错，不猜链接、坐标或引用 ID。

页码从 **1** 开始；位置采用 EmbedPDF 页面空间，左上角为原点，单位为 PDF 点，不含当前阅读缩放和附加旋转。文字选区保存公开接口返回的逐段矩形，不以外包大框替代跨行／跨栏选区；多个页面按页码递增保存。页级引用的矩形列表为空，仅保证跳页。解析服务接入时须将自己的页码、裁切和坐标转换到此约定，不能直接把原生 PDF 左下角坐标或屏幕像素填入。

工程命令 `createCitation` 接收当前 PDF 路径、`CitationInput` 和可选的读取时文档快照 `sourceDocument`，校验已登记身份及定位证据后串行复用或新增 ID。请求中的 `sha256` 必填，仅用于创建时版本校验；去重按文档身份、类型、文字和页／区域比较，不比较哈希。输入与当前文件字节一致时直接接受；字节变化时，读取快照与当前记录须属于同一文档身份和原始来源，且各自字节匹配对应记录的原始或批注版本。这样连续批注保存后仍能使用读取时的定位证据，不需要持久保存哈希历史。未提供快照时只能用当前记录核验原始或最新批注版本；无法核验的版本拒绝登记。`resolveCitation` 接收短链接，查字典后通过文档身份获取当前路径，并检查文件存在；页面定位时继续校验页码、尺寸和区域，不以引用中的原始哈希拦截。未知 ID、缺失字典／PDF 和损坏字典均明确报错，不猜测目标，不重分配旧 ID。通过应用改名、移动或重新关联同内容文件后旧链接继续生效。普通未登记 PDF 须先添加为工程材料。

字典只由工程命令写入；同一工程进程内的并发新增经队列串行执行。先完整写入并同步随机临时文件，再同目录替换字典，失败或替换前中断不截断旧字典；残留临时文件不是正式数据。当前不承诺任意外部程序同时改写字典的合并，Agent 后续须调用公共引用命令，不直接编辑字典。

### Agent 读取与评论

Agent 使用现有 `read`（支持 `offset`／`limit`）和 `bash`（Windows PowerShell）读取、搜索解析稿，直接复用段落旁的完整链接；回复和 `write`／`edit` 不需要创建或转换引用。`text/` 是论文转录，`map/`、`explanations/`、`notes/` 中的成果不能替代论文原文。普通问答不自动写成果，文档写入继续使用读取基线保护。

`resolve_reference` 接收完整无痕引用链接或原生批注链接。共享工程命令为 `resolveReference`，输入均包含 `link` 和可选的 `sourceDocument`；相对批注链接来自 Markdown 时明确传入工程内文档路径，对话链接以工程根目录为基准。结果包含实际 PDF 的 `path`、`documentId`、当前 `sha256`、`pages` 及 `status: available`。未知 ID、缺失 PDF、删除的批注、页码／尺寸不符均报错，不猜测目标。读取不创建引用、不修改 PDF，也不强制渲染图像。

`manuscript` 是主要阅读入口：返回 `status`（matched／multiple／ambiguous／unmatched）、`locations` 与可选缺失原因。每个位置包含当前解析稿 `path`、`blockId`、完整块 `link`、1 起始 `linkLine`、`startLine`、`endLine`。行号实时解析 Markdown 链接，不计代码示例或笔记中的复用；重复出现明确为歧义。正文使用 read 读取，不返回 mapping.json 的旧 block.text。独立段尾链接包含前一个正文块的范围。手动选区按页码与区域相交找块，跨块返回多处，重叠块明确歧义，不按最近距离猜测；无解析或链接缺失明确反馈。

`discussions` 按根批注分组，包含对应 `blockIds` 和保留 `id`、`parentId`、`replyType`、`type`、`comment`、`author`、`target` 的条目。普通批注／评论／追评链接均沿 PDF 原生回复关系展开完整讨论，并发现同段其他独立讨论；位置相同不会合并独立根。每次读取已保存 PDF，旧链接可看到新追评。缺父节点或循环等关系通过 warnings 报告，讨论 status 为 missing-parent／cycle、rootId 为 null；保留条目及 parentId，不用追评自身坐标确认正文归属。`excerpt` 只保留用户实际选中文字（selection），无则为 null；`comment` 是链接指定批注的文字，不冒充原文。需要图像时按需调用 read_pdf。

`create_annotation` 接收已有解析块完整链接和 `comment`，复用登记页码与区域在块旁创建原生便签评论，保存并读回核对后才返回工程根目录相对的 `#annotation=` 链接。页级引用、手动区域或无可靠块位置均明确报告定位不足，不生成新引用或猜坐标。PDF 已在阅读器中打开时通过阅读器刷新待存批注并复用自动保存；未打开时使用 PDFium 写入和同一 `savePdf` 原子保存入口。失败不回退覆盖其他版本，外部修改、保存失败及取消明确反馈。此工具只按用户要求创建评论，读取与复制链接不会触发它。聊天标签由 STE-95 集成，复用同一正文位置与讨论解析入口，不默认发送截图。

PDF 的「复制引用链接」复制普通 Markdown 文本；文字标签压缩空白后取前 25 个字符，超长加省略号，引用中的完整选中文字与链接地址不变；无选中文字时仍明确显示 PDF 页码。文字选区菜单和右键菜单提供同一操作，「框选引用」用于图表等区域，原生工具栏的「引用」页签提供框选、整页选择、复制和取消。框选和整页选择仅保留临时状态，重新选择替换旧选择；点击「复制引用链接」时才保存引用：同一文档身份、引用类型、文字及全部页面坐标完全相同则复用已有 ID，否则新增记录。框选不做坐标容差或模糊合并；重复复制当前选区复用，重新框选改变范围则新增。Esc、取消图标或提示条的关闭按钮清除临时框选预览，不写字典，也不清除引用跳转的定位高亮。整页选择后复制明确生成页级链接。Markdown 阅读点击或源码 Ctrl＋单击通过同一解析入口定位，保留文档草稿和编辑状态，通过普通标签切换回到文档，各标签保留自己的阅读位置。复制本身不生成持久 PDF 批注或文档反查记录。

跳转高亮为临时展示，不改变 PDF 字节或批注。位置转换使用 EmbedPDF 的 Scroll 接口，随缩放、旋转和布局更新。当前完整 Viewer 2.15.1 未开放自定义页面层插槽，仅展示层挂载点依赖其 shadow root 的 viewport 结构；选区取证不依赖 DOM。升级阅读器时须重跑高亮位置的桌面集成测试。

PDF 文档引用侧边卡片从磁盘上的 Markdown 实际链接重建，不另存使用索引，也不删除引用字典中的历史记录。统计工程文件树内的 `.md` / `.markdown`，排除原始材料和解析稿目录 `text/`、出处目录 `sources/`、隐藏目录及 `node_modules`；聊天会话、仅复制的引用、代码和公式中的示例链接不产生反查记录。保存、外部编辑、改名／移动、重开或刷新后重新收集；自动保存完成前的编辑不计入磁盘使用位置。

阅读器的「文档引用」按钮统一列出无痕引用与原生批注的使用位置，不在 PDF 上绘制常驻引用框或页角按钮。点击卡片来源定位原文，无痕区域引用显示临时黄色高亮，批注链接选中原生批注。同一 ID 在多篇文档或同篇多处使用逐一列出标题、路径、所在段落行号与上下文。点击列表定位并突出显示 Markdown 中的实际链接，切换回 PDF 标签恢复其页码、滚动、缩放与布局，不重放上一次引用定位。目标文档版本已变或存在未保存草稿时保留内容并提示重新定位，不套用旧索引猜测新位置。

无痕引用的临时高亮使用展示层及公开 Scroll 坐标转换，不导入为原生批注，不修改 PDF。定位高亮在 PDF 内操作时保留，仅在离开 PDF 标签后清除。原生批注由 EmbedPDF 管理并在变更后自动保存到工程 PDF，两类链接分别保留既有身份。字典损坏或使用文档读取失败时清除对应的反查结果并显示错误，不把旧结果当最新索引。

## 解析候选

百度解析每批次只生成一份完整正文 `text/<batchId>/paper.md`，图片位于同目录下的 `images/<sha256>.<png|jpg>`，`batchId` 为 32 位小写十六进制。正文按阅读顺序组织，图片就地出现，每段末尾用简短的 `[原文](paper://cite/...)` 回查 PDF；不显示独立块 ID、供应商图片路径或页末重复图片，也不另存逐页 Markdown。任务状态、供应商原始返回与块映射分别保存在隐藏目录 `.paper30min/parsing/<batchId>/` 的 `run.json`、`result.jsonl`、`mapping.json`，不进入文件树。独立批次保留旧有效产物，不自动删除或覆盖；已有 `text/candidates/<batchId>/` 布局继续原位读取、恢复和校验，不自动迁移。解析正文在审阅前后均可编辑，同一份 Markdown 始终是当前正文，审阅状态由任务记录区分。

`run.json` 的 `formatVersion` 为 `1`，保存工程身份、批次、PDF 文档记录、端点、请求模型、任务号、阶段、页数、累计本机处理耗时和错误；完成时保存原始返回、映射和正文的 SHA-256。阶段为准备、提交、提交结果不明、查询、下载、映射、停止、本机失败、云端失败或候选完成。重开将无活动进程的中间状态呈现为可恢复；磁盘上的提交中状态视为结果不明，必须关联百度任务号才能继续查询，禁止自动重传 PDF。明确的鉴权、参数或额度拒绝视为未受理，用户修正后可主动重试；已下载原始结果但本地映射失败时也允许主动建立独立新批次。停止等待在途提交回执并保存任务号，不承诺取消云端计费。退出超过两秒会强制结束工程进程，未收到回执仍按结果不明处理。

`mapping.json` 的 `formatVersion` 为 `1`，绑定 `projectId`、`batchId`、`document` 和 `rawSha256`。每块保留 `id`、供应商 `vendorIds`、`label`、原始 `text`、统一 `citation`、本地 `images` 路径和 `limitation`。块 ID 为 `<batchId>:p<1 起始页码>:b<供应商块号>`；同批次恢复稳定，不跨批次复用块号。`text` 是解析时的原始摘录，纠错不改写这份来源记录；读取、搜索和生成须以当前 Markdown 为准，不能把原始摘录当成修正后正文。原文同组多区域一起保存，任一区域不可信则整块降为页级。OCR 块使用 `region` 引用，不能声称逐字精确。STE-98 自动短句精细引用已取消；用户手动精细选区继续保留。

供应商坐标按图像尺寸缩放到 PDF 点坐标；仅接受无旋转、CropBox 与原点一致的 MediaBox 重合、未开启图像预处理且宽高比通过校验的页面。其余情况保留正文并明确降为页级，不编造矩形。当前服务批次未提供可独立核验的绝对页号，按校验后的 JSONL 返回顺序对应 PDF 页；页数、尺寸或重复非空页异常会失败，但同尺寸页面的语义换位无法自动检出，仍需后续逐页审阅。

图片支持供应商 Base64 或受限百度 HTTPS 域名下载，正文图片通过 Markdown 语法树重写为本批次相对路径；HTML 表格转换后同样重写。公式、图表和表格另按可信区域从原 PDF 裁切，保存在图片清单供后续核对；正文已有图文时不重复展示裁切图，空白视觉块则在原位置显示裁切图。图片清单记录页码、摘要及可用的供应商路径或块 ID；无法可靠关联的供应商图像仅在清单中保留页级关联，不推测属于哪个块。打开、审阅和日常 Agent 准入均核验当前 PDF、映射和图片摘要；Markdown 允许纠错，不再与初次解析摘要作相等校验。重新解析仍不得覆盖旧批次。原始 JSONL 可能含服务签名地址，仅用于保留现场；离线展示依赖本地图片，不依赖其 URL。

## 解析审阅

「开始审阅」创建普通历史中可见的 Pi 会话。这里的审阅是原文转录校对：以 PDF 原页为依据，逐字逐句将论文完整、忠实地还原到同一份 Markdown，现有解析稿只是底稿。Agent 自主使用 `read_pdf` 读取完整原页，按需读取对应正文，逐句核对文字、阅读顺序及跨页衔接，逐项核对公式符号、表格单元格、原图与图注，并覆盖脚注、参考文献和附录等实际内容。保留原文语言、措辞和原作者的错误，不以摘要、改写、翻译或学术评价替代原文；允许将印刷排版转换为 Markdown 阅读结构。应用不调度逐页提示，也不生成第二份正文。

`complete_review_page` 只接受本会话实际读取过的下一连续页。提示词要求先完整校对、保存修正，再读取保存后的正文对照原页确认，才能标记完成；无法辨认时调整整页渲染比例重新读取，仍无法确认则在会话报告具体位置并暂停，不标记该页完成。工具强制校验整页读取和连续页码，转录准确性仍需真实模型质量验证。`run.json` 的 `reviewedThroughPage` 保存连续完成页码，`reviewSessionId` 关联最近审阅会话，`reviewError` 保存停止或失败原因；运行中状态不作为持久断点。同批次不能并发审阅。

中断后「继续审阅」创建新的可见会话，从最后完成页的下一页重新核对，保留既有正文修正。不记录半页状态、疑点数据库或自定义摘要；转录疑点留在会话，不混入原文。全部页完成且 PDF 仍匹配后开放日常 Agent；口头声称完成不能代替进度。PDF 身份或内容改变后旧结果失效。后续正文纠错、生成失败不清空已完成进度，也不重传 PDF。完成审阅记录一轮转录校对完成，不代表应用独立证明正文无误。

提示词要求仅在对照 PDF 确有必要时修正 `text/` 中的 Markdown，解释、翻译和扩写另写成果。保留已有引用 ID；增补、拆分或合并使用应用已登记的区域或页级链接，不改指旧 ID 的目标。

## 建图与记忆卡片

阅读地图或论文精解入口可生成两类成果；缺少完整审阅时引导到论文解析。建图读取当前已审阅正文，按真实结构与顺序生成充分讲解，覆盖有实质内容的附录，不另设深挖阶段。重新生成前一次列出将替换的地图和精解，用户确认后记录清单、正文及旧成果的内容基线。

普通 Pi 建图会话使用 read/write/edit，将候选写入 `tmp/mapping-<id>/`，最后写 `result.json`：`{"map":"map.md","explanations":["explanations/01-引言.md", "explanations/02-方法.md"]}`。数组明确记录阅读顺序，不能以文件名字典序代替。应用检查非空 Markdown、真实可解析引用和原确认基线后，将新文件保存到 `map/<id>/阅读地图.md` 与 `explanations/<id>/`，再一次切换清单中的地图与精解。文档内导航和图片按正式路径计算相对链接。

停止、生成失败、候选不完整或基线改变时保留候选与旧成果，不登记部分成功。重开后可在原建图会话继续；续接仍使用原确认基线，不能覆盖期间新增的用户修改。成功后才将未被改动的旧目标移入系统回收站，回收失败保留文件并报告。发布状态随 Pi 会话保存；它记录已发布事实，不表示模型内容已获独立质量证明。

建图会话不创建分支，避免复制同一发布任务；深入讨论成果可新建普通会话，普通讨论与记忆卡片会话仍支持分支。

「记忆卡片」由用户在对话中按需调用，指定原文、笔记或讨论的范围，生成普通的 `memories/*.md`。卡片可自由编辑、改名和搬迁，不需清单登记。提示词要求保留必要解释、推理、条件、待核实问题和实际存在的来源链接；没有来源的讨论理解不伪造引用。普通聊天、建图和精解不自动生成卡片，不提供复习调度或独立卡片数据库。

## 本机配置

Electron `userData/preferences.json` 保存 `defaultFolder` 与最多 20 个最近工程的路径和名称。默认目录只影响后续新建，不搬迁已有工程，也不限制打开位置。默认目录不存在或不可写时要求重新选择，不自动改存其他位置。该配置不放进工程，不随工程搬迁。

工程进程对本应用的操作串行处理，创建取消可独立送达。后续外部编辑与 Agent 并发写入不能仅依赖该队列，须按 STE-78、STE-81、STE-86 的正文基线与冲突契约接入。

模型和代理配置保存在本机 `agent-settings.json`；API 密钥使用 Electron `safeStorage` 加密，不进入工程或会话。复制工程到另一台机器后需要配置该机器的模型与凭据。

新版产品 Skill 默认提示词位于应用的 `skills/`（仓库路径 `app/skills/`）。「设置 → 产品 Skill」可编辑并保存本机覆盖文件 `userData/product-skills/`；保存按内容 SHA-256 检查冲突，失败保留草稿。每次调用把当时实际使用的提示词和版本写入用户消息，历史重开不受后续提示词修改影响。本机覆盖不随工程搬迁，旧根目录 `skills/` 的文本工具协议不在新版加载。

百度解析配置独立保存在本机 `parsing-settings.json`，Token 同样使用 `safeStorage` 加密，仅在请求时解密。解析复用 Agent 的直连／环境／自定义代理选择；停止和查看任务状态不依赖凭据配置。机器配置不随工程搬迁，已有候选可离线阅读。

## Pi 会话

普通对话与审阅共用 Pi SDK 的 JSONL 持久化，均开启原生自动上下文压缩，不另建聊天数据库或摘要机制。会话包含用户消息、模型回复及 Pi 元数据；历史 `cwd` 可能保留原工程绝对路径，但重开时使用当前工程目录，不以历史路径过滤会话。普通会话分支建立新的原生会话文件，原会话可继续打开；审阅使用「继续审阅」按工程进度新建会话，不从历史消息分支。空会话在首次消息写入前不保证落盘。

运行、补充消息队列和输入草稿是临时状态。停止清空待执行补充消息，保留已收到的回复及已完成文件修改；停止后迟到事件不得追加到会话，排队中的文件写入在提交前检查取消。会话按工程目录与 Pi 会话身份隔离，停止不等待文件操作队列。退出取消运行，工程进程未及时结束时由主进程在两秒期限后终止；进程强制终止不保证保存尚未落盘的流式片段。Pi 原生工具调用、结果、改动与冲突数据保存在对应消息中，历史重开按 toolCallId 关联；普通对话可根据用户请求连续修改成果和运行 PowerShell，仍保留原始论文保护、写入冲突检测与取消检查。

## Agent 文件与 Shell

read、write、edit 复用 Pi 原生工具，工程服务提供真实读写。读取限定工程内 UTF-8 文本（2 MiB），拒绝父目录、内部隐藏文件、符号链接及 PDF。已有文件必须先 read；edit 使用已读取的基线，write 使用同一基线。冲突返回基线、当前磁盘和本次拟写入内容，先重读再决定整合，不覆盖双方输入。新文件独占创建，已有文件使用与界面保存相同的暂存、同步和替换流程；任意外部编辑器的最后检查与替换之间仍存在文件系统竞态。

`text/` 中的 Markdown 允许界面及 Agent read/write/edit 修正，仍使用正文基线与冲突检查。`sources/`、`text/` 中的图片和其他非 Markdown 文件、任何 PDF、已登记材料及内部文件保持保护；百度解析通过受限二进制入口落地。审阅前可手动阅读和编辑，日常 Agent 发送须工程论文存在匹配当前 PDF 的完整审阅结果。

Markdown 保存统一调用 `DocumentReferenceProcessor`，界面与 Agent write/edit 共享转换后的内容和保存基线。直接复用完整 `paper://cite/<id>` 链接，不新增块 ID 转换器或 write_note。旧 `paper30min-source:` 与 `paper30min://source/` 链接明确报错；代码示例不转换。

bash 在 Windows x64 上使用 PowerShell，输出截断及退出错误复用 Pi，默认超时 120 秒。每次 Shell 建立带 kill-on-close 的 Windows Job Object，正常退出、取消及工程进程退出时子进程随 Shell 退出。模型密钥不放进子进程环境；输出在 Pi 保存全文临时文件前脱敏。工具卡片提供本次 Shell 新增文件入口，已有文件变更可用 read 查看。

Shell 按用户确认采用受信任主机执行，没有强制文件隔离；工作目录与 Job Object 不构成文件沙箱。模型指令禁止借 Shell 修改受保护文件，但恶意或不遵守指令的脚本仍具有当前用户权限。越界、系统修改和上传／发布工程内容须有明确任务授权，本切片不实现完整权限管理。审阅任务不受日常 Agent 的完整审阅门槛限制。

## Markdown 编辑与外部协作

UTF-8 Markdown 正文为权威（含 BOM），单文件编辑预算为 2 MiB。打开、阅读和切换视图不写正文。CodeMirror 仅应用用户编辑范围；未修改范围的 CRLF、LF、混合换行、注释、空行和尾随空格保留。新输入换行沿用文档首个换行样式。阅读渲染不反向生成 Markdown，原始 HTML 按文本显示。公式由 KaTeX 渲染，图片限工程内相对路径，链接可打开工程文件或 HTTP/HTTPS 外部网页。工程外文件与符号链接图片不加载。

保存为显式操作，可用 Ctrl+S。各标签独立保留草稿和撤销记录，切换标签、视图和设置不丢编辑；关闭脏标签、离开工程或退出窗口需确认放弃。草稿尚不提供崩溃恢复。

Node 读入时返回正文的 SHA-256 基线。保存先检查基线，再在同目录写入并同步临时文件，替换前再次核对磁盘内容；失败不截断旧正文。此检查能识别普通外部写入，但文件系统不提供面向任意外部编辑器的原子 compare-and-swap，不能承诺消除最后一次检查与 rename 之间的竞态；后续 Agent 写入必须复用工程服务并遵守重读契约。

无本地修改时载入外部更新；双方修改时保留当前草稿并显示磁盘内容，禁止直接覆盖，第三次外部更新继续显示最新磁盘内容。删除／改名保留已打开标签内的文本并提示。语义整合由后续 Agent 切片接入，本切片不模拟合并。
