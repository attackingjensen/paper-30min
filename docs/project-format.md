# 本地工程文件契约

本契约对应 v2 的 S1/S2 与 STE-69、STE-76。工程围绕创建时的论文，正文以普通文件为权威，首版不使用 SQLite，也不自动初始化 Git。

## 文件组织

```text
工程文件夹/
  paper30min.json       # 轻量清单，formatVersion = 1
  text/paper.pdf        # 创建时复制的工程论文
  map/                 # 阅读地图
  explanations/        # 按顺序组织的论文精解
  notes/               # 笔记与用户文档
  memories/            # 记忆预留区，尚无记忆服务
  tmp/                 # 临时脚本与产物
  .pi/sessions/        # Pi 原生会话预留位置，尚未接入
```

允许增加普通文件和目录，文件树直接从磁盘读取，不要求逐个登记。内部隐藏目录、隐藏临时文件与 `node_modules` 不展示。当前可手动刷新，窗口重新获得焦点时刷新；正文编辑与持续监听由 STE-78 接入。

清单字段：

| 字段 | 含义 |
| --- | --- |
| `formatVersion` | 工程格式版本，目前只接受 `1` |
| `id`、`name` | 工程身份与名称 |
| `paper` | 固定工程论文的 `id`、相对 `path`、原文件 `sha256` |
| `materials` | 参考材料身份与相对路径，使用同一记录格式 |
| `map` | 地图相对路径，未生成时为 `null` |
| `explanations` | 按阅读顺序排列的精解相对路径 |
| `translations` | 目标语言到全文译文相对路径的映射 |

相对路径使用 `/`，不允许父级穿越、绝对路径、Windows 保留名称或指向工程外的符号链接。文档身份在应用内改名／移动后保持不变，相关清单字段随路径更新。出处记录由 STE-80 建立，届时复用文档身份和版本；本切片的移出确认提示引用失效，不声称已有引用检索或改写功能。

普通新增文件不一定具有已登记的文档身份。工程论文与参考材料必须有独立身份和路径；不能把参考材料设为工程论文，也不能通过材料移出入口删除工程论文。

## 创建、失败与搬迁

创建前展示名称和完整工程路径，用户可修改名称和本次保存位置。保存位置必须已存在且可写，同名子目录不覆盖。新目录由独占创建取得；PDF 复制到 `text/paper.pdf`，再计算 SHA-256 和写入清单。复制、初始化和本机最近工程登记均成功后才返回成功。

复制或初始化失败、用户取消、正常退出应用时取消未完成的创建，清理本次拥有的目录，不登记成功工程。登记开始后是提交点，迟到的取消不撤回已提交工程。强制杀进程或断电不保证清理未完成目录；没有成功登记的目录需要用户检查，不自动删除。

外部 PDF 保持不变，其原路径不写入工程清单。后续使用工程内副本；整体复制或移动工程后，可从任意位置重开。搬迁不携带机器配置；当前没有 Pi 会话内容或阅读位置可恢复，这些能力由后续切片建立。

材料添加先完整复制，再登记身份。改名／移动只操作文件，目标父目录须已存在且目标不能覆盖；清单保存失败时尝试回到原路径。文件移动依赖本地文件系统硬链接提供不覆盖保证，跨卷挂载点不支持，应通过添加材料复制。

外部改名／移动后，缺失文件显示重新关联。关联文件必须与登记的 SHA-256 一致，不能将另一篇论文冒充固定工程论文；工程外的匹配文件会复制进工程，工程内的匹配文件更新相对路径。文件内容已经被修改时保留缺失提示，版本替换与旧出处失效由后续出处契约承接。

移出参考材料通过系统回收站执行，确认提示相关引用失效，研究成果保留。回收站失败时不移除清单记录；文件已移入回收站而清单保存失败时，明确提示从回收站恢复再刷新。

## 本机配置

Electron `userData/preferences.json` 保存 `defaultFolder` 与最多 20 个最近工程的路径和名称。默认目录只影响后续新建，不搬迁已有工程，也不限制打开位置。默认目录不存在或不可写时要求重新选择，不自动改存其他位置。该配置不放进工程，不随工程搬迁。

工程进程对本应用的操作串行处理，创建取消可独立送达。后续外部编辑与 Agent 并发写入不能仅依赖该队列，须按 STE-78、STE-81、STE-86 的正文基线与冲突契约接入。
