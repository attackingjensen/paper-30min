## 阻止进入完整开发的发现

### ResNet 第 5 页 Table 1：复杂表格被拆成多余列

原 PDF 为 7 列：layer name、output size、18-layer、34-layer、50-layer、101-layer、152-layer。AI Studio 返回 HTML 把 `152-layer` 表头设为 `colspan="3"`，其数据行总宽度扩展至 9 列。

例如原 PDF 的 conv3_x / 152-layer 为一组 `[1×1,128; 3×3,128; 1×1,512] ×8`。结果在多余列中复制同组结构并写入 `×4`，又把 `x8` 放到独立单元格。conv4_x / 152-layer 的 `×36` 也被拆到独立列。这不仅是排版差异：按表头解析会让结构和重复次数关联错误，可能误导后续建图或问答。

同页 Table 2 的 `27.94 / 27.88 / 28.54 / 25.03` 简单数字表正常。Docling 基线的同一复杂表也有拆列、括号与倍数分散，不能把 Docling 当作真值，也不能声称云端在此全面退化；应以原 PDF 为判断依据。

### 来源适配需要保留分组多框及核实页序

知识蒸馏首页作者信息被合并到一个非空文本块，同 `group_id` 的后续块有空文本和各自坐标。把合并内容只绑定第一框会产生错误出处；来源应保留同组多个区域，细粒度字符绑定仍待验证。

JSONL 按批返回，每批有 `layoutParsingResults`，初测没有绝对 `page_index`；工具以官方示例顺序分配页码并标记 `jsonl-order`。页面完整数量不等于页序正确，需要逐页内容锚点或独立来源验证，不能直接作为产品可信页码。

## 结论与下一步

API 和内容坐标链路具备继续试验的条件；目前 **不满足复杂表格验收，U2 未通过**。不能先接入产品再把损坏 HTML 当完整成功。

后续可核对供应商支持的表格参数，做针对性重测；或明确设计复杂表格保留原始图像、结构化内容降级的行为，再评估是否满足阅读契约。参数试验不能暗中改写结果，视觉降级也不能冒充无损表格解析。确定路线后还须补全逐页锚点、公式/附录、扫描和几何专项；U3 的来源验证、离线资源、安全替换和历史引用兼容均尚未开发。
