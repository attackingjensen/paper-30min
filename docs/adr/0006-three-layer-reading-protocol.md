# 三层阅读协议与工具化取证

[ADR-0002](0002-follow-paper-structure.md) 确立了"按论文实际一级章节组织精读"，但旧协议的生成方式是"每类章节一个提示词、单次注入章节原文"：模型机械通读被截断的文本，产物无地图、无分层、无出处，读一篇长论文的上下文成本高且不可核验。

项目决定把阅读协议改为三阶段（迭代而非推翻 ADR-0002：原文章节与精读部分概念全部保留，节树与地址空间继承"按原文结构"）：**建图**（用户显式触发，两调用自底向上：先全部节薄摘要、再合成阅读地图）→ **深挖**（按需：配方打底 = L1 地图 + 全部节薄摘要 + 当前节原文全送 + 当前节页图±1，之后模型用四件只读工具 read_section / search_paper / get_figure / get_page_image 越界取证，Rust 驱动循环、无工具调用即完成、步数上限 12）→ **综合**（手动触发复述稿，未深挖节明确标注）。产物纪律为 EXTRACTED：每条论断带出处指针，无出处不写。技能库从"每类章节一个提示词"改为"协议各阶段提示词（建图两段/深挖/综合）+ 按章节类型叠加的关注点数据"。

工具调用的传输形态选择**文本协议**（模型输出约定格式的调用块，Rust 解析执行并把结果续入上下文），不依赖模型底座的原生 function-calling——该能力未经验证，文本协议零能力假设、解析失败可喂回模型自我纠正，与"错误即指令"一致。两条相关取舍被明确否决：地图不提供"建议深挖节"判断（只保留事实指针，选择是用户的）；不设阶段条/向导式流程 UI（规范阅读靠信息架构本身，见 #43）。代价是接受多次模型调用的编排复杂度与提示词工程成本，换来的是 token 预算可控（跨节上下文来自地图与薄摘要，绝不重发其他节原文）与产物可核验。

来源：Wayfinder 地图 #35、设计定稿 #41、验证 #46、规格 #48/#55。
