# 阅读进度与协议产物的数据模型

旧数据模型中阅读进度从精读结果派生（不生成结果进度就永远不动），连续阅读打卡是瞬时派生（重读旧节会改写历史打卡）。项目决定：**已读完 = 用户对精读部分的手动标记**，可撤销、不以有精读结果为前提；阅读进度 = 标记比例，前端派生不落库；**打卡 = append-only 活动日表**，撤销标记不回收已发生的活动日；协议产物（阅读地图、节薄摘要、深挖结果、复述稿）随论文记录的既有整记录写入缝持久化，不开专用桥命令。迁移用快照判据回填，事务内全有或全无、失败拒绝启动；整库导出幂等合并。

被否方案：给结果表加状态列（中断部分结果的结构化属于产物契约层）；进度自动推断（「看薄摘要就够」的节无法被推断，手动标记把选择权给用户）；撤销标记回收当日打卡（历史不应被改写）。代价是用户多一个手动动作，换来进度、打卡与成果三条时间线各自可信。
