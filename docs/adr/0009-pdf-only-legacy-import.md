# 仅以旧 PDF 批量创建新工程

旧书库与 v2 工程的内容身份、成果和会话模型不同。选择性迁移笔记与回忆卡需要处理作者不明、附件归属和旧引用，旧成果重建还需要一致性备份、摘录接口与单独的模型验证。用户决定只复用原始 PDF，接受其余旧内容不进入新版，以缩小兼容范围，并让所有研究从新版正常流程开始。本决定替代 [ADR-0008](0008-legacy-library-migration.md)。

用户设置好默认工程文件夹后，从旧桌面书库取得原始 PDF，复用普通新建工程能力，为每份 PDF 创建独立工程。PDF 复制到工程内的 `text/paper.pdf`，工程不依赖旧路径；工程名默认取可获得的 PDF 文件名。旧版原始文件统一存为无扩展名的 `pdf`，因此使用 `pdf-<论文 ID>` 区分，导入前可修改，不读取旧标题或原文件名等数据库元数据。除 PDF 外，不导入旧笔记、回忆卡、图片和其他附件、解析缓存、生成成果、会话、阅读状态或技能覆盖。创建完成即结束，不自动解析、审阅、建图、生成或调用模型；后续操作由用户主动发起，沿用新版正常入口与有效解析门槛。

批量创建逐份提交，单份失败不影响其他项；同名目录不覆盖，成功项重试不重复创建，失败与中断后可继续处理。PDF 读取与安全复制、命名冲突和导入进度由实施设计确定。旧书库及原文件保持原样，不移动、修改或删除；新版不再承担旧 SQLite 一致性备份、备份恢复、旧成果摘录或重建 Skill。程序升级的兼容和旧数据保护要求仍须独立验证。

决定来源：2026-10-15 用户确认的 PDF 单独复用策略；实施范围见 [STE-87](https://linear.app/steven-liang/issue/STE-87)，原旧成果重建票 [STE-88](https://linear.app/steven-liang/issue/STE-88) 取消。
