# 阅读进度与协议产物的数据模型

旧数据模型有两个结构性缺陷：阅读进度从精读结果派生（不生成结果进度就永远不动，且"看过"无法表达）；连续阅读打卡是瞬时派生（重读旧节推进结果更新时间，会改写历史打卡）。新阅读协议（[ADR-0006](0006-three-layer-reading-protocol.md)）又带来三类新产物（阅读地图、节薄摘要、深挖结果/复述稿）需要持久化。本 ADR 把这些数据模型决定固化下来。

决定：**已读完 = 用户对精读部分的手动标记**（新表 `read_marks`，可撤销、不以有精读结果为前提），阅读进度 = 标记数/部分数、前端派生不落库；**打卡 = append-only 活动日表**（`activity_days`，导入/结果/中断保留/标记四个写入缝各自插入，撤销不回收——打卡是"发生过阅读活动"的历史事实）；**协议产物**落 `protocol_products(paper_id, kind, part_id, body, updated_at)`；三者均随论文记录 DTO 走既有 `putPaper` 整记录写入缝（[ADR-0004](0004-paper-lifecycle-module.md) 的缝），不开专用桥命令。迁移用快照判据回填（判据常量写死在迁移代码，不与运行时常量共享），事务内全有或全无、失败拒绝启动；整库导出幂等合并。

被否方案：给 `analyses` 加状态列（否——中断部分结果的结构化属于产物契约层，不污染结果表）；进度自动推断（否——"看薄摘要就够"的节无法被推断，手动标记把选择权给用户）；撤销标记回收当日打卡（否——派生模型无法兑现"不回收"，且历史不应被改写）。代价是用户多一个手动动作，换来进度、打卡与成果三条时间线各自可信。

来源：Wayfinder 地图 #35、设计定稿 #40、规格 #51；协议产物表见规格 #55。
