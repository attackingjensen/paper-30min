# 论文生命周期由 papers.js 统一拥有

论文记录的结构、不变量、章节投影与写入规则散落在 [`public/js/app.js`](../../public/js/app.js) 的两处创建点、15 处写入点与 6 处投影调用中；[`public/js/db.js`](../../public/js/db.js) 是只有 `app.js` 消费的 55 行存储薄层，不构成有意义的缝。项目决定建立 `public/js/papers.js` deep module，统一拥有论文记录生命周期：吸收 `db.js`（IndexedDB 访问成为模块内部实现，并通过可注入的 store 适配器向测试开放），收编两处导入映射、精读部分投影、阅读进度与打卡活动日派生，以及全部写入规则——每次写入由模块统一变更、推进 `updatedAt` 并持久化。记录保持普通对象，模块对外是函数式接口，`app.js` 保留 DOM 渲染与事件处理。阅读生成（组提示词、截断、流式与中断）不属于该模块，未来由独立的生成任务模块经 `saveAnalysis` 缝提交结果；`maxChars` 截断归属生成而非记录。

模块维护三条不变量：阅读进度只从精读结果派生、不落库，生成被中断保留的部分结果计入进度；重新切分作废除摘要外的全部结果（摘要原文未变时保留摘要的结果与翻译）并在界面提示，杜绝按位置性 id 把旧结果静默重挂到新章节；打卡活动仅指导入论文或产生精读结果，该语义已写入 [`CONTEXT.md`](../../CONTEXT.md)。

两处真实备选被否决：会话对象式的不透明记录要求重写全部直接读取 `paper.*` 字段的渲染代码，收益为零；重切分的逐节精细比对依赖章节合并语义、难以测试，而重切分是低频的推倒重来动作，简单作废规则的代价可接受。
