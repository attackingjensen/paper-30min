# Spec: pdf-import

> 状态：已批准  
> 所属能力地图：[文本中心阅读核](capability-map.md)  
> 依赖：[project-core](SPEC-project-core.md)、[document-core](SPEC-document-core.md)（均已批准）  
> 协同：[arxiv-import](SPEC-arxiv-import.md) 的显式 PDF 回退交接  
> 下游：`agent-integration`、`pdf-comparison`

## Objective

为没有可用线上结构化正文的论文提供 **PDF 云端解析到同一规范文档树** 的导入能力。首版沿用当前百度 AI Studio 任务服务与 `PaddleOCR-VL-1.6`，保留远程任务恢复、费用确认和本机凭据边界，但不再把 Markdown 解析稿、PDF 坐标字典或逐页 Agent 审阅作为阅读权威与使用门禁。

PDF 来源、云端解析结果和当前正文是三个不同层次：原始 PDF 快照用于追溯、重新解析和原页对照；不可变解析快照用于离线重新转换；current JSON 树才是界面与 Agent 的唯一当前阅读权威。未经完整 LLM 审阅的解析稿只要通过机器完整性检查即可阅读和使用 Agent。

质量信息只由来源事实、机器诊断和实际核验范围组成。用户或 Agent 可以记录核验过的章节／范围；正文修改后，对应范围自动成为“修改后未复核”，不得以单一质量分数或全篇“已审阅”代替这些事实。

本模块成功时，应满足：

- 本地 PDF 和 arXiv 固定版本 PDF 都能进入同一文档树，工程与 `paper.id` 不因重解析而改变。
- 每个新云端任务都须显式确认；提交结果不明时绝不自动重传，恢复优先复用原任务号。
- 全部页面返回且候选完整后才首次发布 current，局部保真问题以机器诊断呈现，不等待 Agent 审阅。
- 重解析形成候选并执行三方合并，旧 current、用户修正和已有核验不会被静默覆盖。
- 核验记录能回答“谁、在什么正文与 PDF 来源上、实际核验了哪些节点”，新增或修改内容不会混入旧范围。

## Scope

### In scope

- 本地 PDF 的只读复制、格式检查，以及 arXiv 固定版本 PDF 的获取与来源谱系。
- 原始 PDF 快照、云端解析快照、规范化页／块事实和本地化解析资产。
- 百度任务提交、提交结果不明、任务号关联、查询、下载、停止、恢复和重复付费防护。
- 云端响应去敏、资源 URL 限制、凭据与机器配置的持久化边界。
- 解析结果到 `document-core` 文档树的确定性转换、页数与块完整性检查、机器诊断。
- 首次全文发布、显式重解析、同快照离线重新转换和候选基线检查。
- 可选 PDF 原页读取、用户／Agent 核验范围、来源证据引用及修改后未复核状态。
- 核验在正文变化、同 PDF 重解析和不同 PDF 快照之间的继承规则。

### Out of scope

- arXiv HTML 获取、版本检查和 HTML→文档树转换，属于 `arxiv-import`。
- unit→PDF 页／区域的语义映射、双向点击同步和同步界面，属于 `pdf-comparison`。
- 通用 PDF 阅读器视觉布局、双栏和标签管理，属于 `reader`／`workspace`。
- Agent 提示词、对话流程和精确任务补查策略，属于 `agent-integration`；本模块只提供来源读取与核验命令。
- 本地 MinerU、本地 Docling 服务、额外云解析提供商和通用 provider 市场。
- 完整 LLM 逐页审阅门禁、主观质量评分、正确率承诺和自动全文修正。
- 旧 PDF 引用字典、`paper://cite`、可编辑 Markdown 正文权威和旧工程迁移。

## Tech Stack

- Electron 主进程与 Node.js utility process；TypeScript、React、受限 IPC／preload。
- 沿用当前 `undici` 网络实现、百度 AI Studio 任务 API 和 `PaddleOCR-VL-1.6`；首版不新增 provider 抽象。
- 沿用 `@embedpdf`／PDFium 检查 PDF 页数、页面几何和按需原页渲染，不引入 Python 或本地模型服务。
- Electron `safeStorage` 与 `userData` 保存解析 Token、代理和用户设置；工程内不得保存这些凭据。
- JSON UTF-8、原始 PDF 字节、受管 JSONL 与内容寻址资产为持久化格式；SHA-256 用于完整性，不作为论文身份。
- 转换为确定性本地代码，不使用 LLM 补齐、审阅或重排正文；文档 schema、ID 和合并遵守 document-core。

## Commands

在仓库的 `app/` 目录执行：

```powershell
npm ci
npm run typecheck
npm run build
npm test
```

针对本模块的真实 Electron、文件系统与受控云服务回归：

```powershell
npx playwright test -g 'pdf-import'
```

默认回归使用本地 PDF／JSONL fixtures 和受控百度服务，不访问真实云服务或模型。真实百度验收须由用户明确授权、使用其凭据并记录实际任务号、模型、PDF 摘要和费用相关界面，不由历史结果或 fixtures 冒充；Linux 构建不能替代 Windows 桌面行为验收。

app/src/main/project/        首次发布、重解析候选与 current 提交组合

现有 `parsing-service.ts`、`baidu-candidate.ts`、`ParsingPanel.tsx` 是改造输入。其远程任务恢复与费用保护可以保留；`reviewedThroughPage` 门禁、`candidate.md` 正文权威、正式 PDF 引用字典和 `materials` 前提不属于新契约。

### PDF 与解析快照契约

PDF 导入使用两类不可变来源快照，通过父级 ID 关联：

```text
sources/<pdfSourceSnapshotId>/
  snapshot.json             # kind: "pdf"；来源、文件名、页数、PDF 摘要
  paper.pdf                 # 原始 PDF 字节

sources/<parseSourceSnapshotId>/
  snapshot.json             # kind: "pdf-parse"；父 PDF、服务、模型、批次和诊断
  result.jsonl              # 去敏并本地化资源引用后的受管解析响应
  facts.json                # 规范化页、块、顺序、几何与资产来源事实
  assets/<sha256>.<ext>      # 云端返回的原始图片等资产
```

- PDF 快照的 `snapshot.json` 记录来源种类、原始文件名、SHA-256、页数和获取时间。本地来源不保存运行所需的外部绝对路径；arXiv 来源另存 base ID、固定 `vN` 和版本化 PDF URL。
- 解析快照通过 `parentSourceSnapshotId` 指向 PDF 快照，不重复复制 PDF。current revision 的 `sourceSnapshotId` 指向解析快照，由谱系可找到原 PDF。
- 解析快照另记录 `parseBatchId`、远端 `jobId`、provider、model、实际解析选项、页数、响应摘要和获取／响应结构诊断；这些是被接受来源事实，不是主观质量评价。
- 获取与响应结构诊断随解析快照不可变保存；转换器和文档验证诊断写入候选／revision 元数据或导入记录，不回写已发布解析快照。
- 只有完整响应经过去敏和基本页级验证后才发布解析快照；不完整响应留在受管 staging，个别资产缺失可按 warning 接受。
- `result.jsonl` 保存可离线重新转换的受管响应。签名 URL、临时凭据和远端资源地址在持久化前替换为本地资产引用或去敏占位；不把含密原始响应写入工程。
- 可记录下载前响应 SHA-256、去敏后 SHA-256、替换数量和失败项目，以说明转换边界。去敏不改变正文块、页／块顺序或几何事实。
- `facts.json` 保存 vendor page／block ID、标签、顺序、页面尺寸、块框、预处理参数和资产映射，不包含 Paper30Min 节点身份。Paper30Min 的 source alias 在转换时映射到这些来源事实。
- 每类快照发布后均不可变。新云端任务产生新解析快照；同快照离线重新转换只产生新候选。原 PDF 字节相同可复用已验证 PDF 快照。
- 旧 `mapping.json`／`candidate.md` 不再是权威，PDF 页／框事实也不构成正式引用字典。`pdf-comparison` 从这些事实和 current 重建派生映射。

## Code Style

共享契约使用可辨识联合和明确的来源谱系：

```ts
export interface PdfSourceFacts {
  kind: "pdf";
  sourceSnapshotId: string;
  sha256: string;
  pageCount: number;
  originalName: string;
  arxiv?: { baseId: string; version: number; pdfUrl: string };
}

export interface PdfParseFacts {
  kind: "pdf-parse";
  sourceSnapshotId: string;
  parentSourceSnapshotId: string;
  parseBatchId: string;
  provider: "baidu-aistudio";
  model: "PaddleOCR-VL-1.6";
  jobId: string;
}

export type VerificationValidity =
  | "verified"
  | "historical-source"
  | "modified-unreviewed"
  | "removed";
```

- 解析任务、PDF 快照、解析快照和 revision 使用不同 ID；不得用 PDF SHA-256 替代其中任何一个身份。
- 诊断包含稳定 `code`、stage、severity，以及可选页码、vendor block ID、source alias 和节点锚点；不向 renderer 返回签名 URL、Token 或原始错误响应。
- `verified` 只表示记录中的实际正文范围已对照所指 PDF 来源，不表示整篇论文正确，也不表示通过模型质量评分。
- 共享类型不得导入 Node 或 React 模块；Node ESM 相对导入沿用 `.js` 后缀。

## Behavior Contract

### 1. PDF 来源与工程身份

1. 本地主论文导入必须来自用户明确选择的 PDF。应用只读复制原始字节，不移动、修改或重新保存外部文件；快照只保存原始文件名与摘要，不依赖其绝对路径运行。
2. 普通文件树中的 PDF 不登记为材料，也不能因移动、改名或打开而成为主论文。只有“导入／更新主论文 PDF”命令能建立来源快照和候选。
3. 本地 PDF 必须先通过格式、页数和预算检查再上传。加密、损坏、空页数或无法读取的 PDF 给出明确错误，不绕过密码、不静默修复后冒充原文件。
4. arXiv 回退接收 `PdfFallbackRequest`，只获取其中固定 base ID／`vN` 的 PDF。不得改取最新版、上一版或用户未确认的其他文件。
5. arXiv PDF 下载遵守 arxiv-import 的 host、HTTPS、重定向和预算政策，并校验实际 PDF 格式；下载成功只形成 PDF 快照，不代表云端解析已确认或正文可读。
6. PDF SHA-256 用于识别相同字节和检查外部变化，不是 `paper.id`。相同字节可复用 PDF 快照，不同字节必须建立新快照。
7. 已有工程的 PDF 更新必须显式确认属于同一论文并携带 `baseRevision`；不同论文不能借“更新”覆盖当前工程。
8. 正常 current 阅读不依赖 PDF 快照始终可用；但重解析、原页对照和新增核验需要 PDF 时，缺失或损坏必须明确报告。

### 2. 凭据、上传确认与机器边界

1. 百度 Token、代理凭据和用户解析设置继续保存在 Electron `userData`；Token 使用 `safeStorage` 加密。清单、来源元数据、revision、导入记录、日志和错误消息不得包含这些信息。
2. 每个新的云端解析 POST 前都显示确认，明确说明将上传哪个 PDF、到哪个服务以及可能产生费用。用户确认“上传并解析”才允许提交。
3. arXiv 回退可以由组合入口用同一次确认覆盖固定 PDF 下载和首个云端任务，但确认必须同时说明上传服务与费用；仅同意下载原页 PDF 不能视为同意上传解析。
4. 恢复已受理任务、查询状态、重新下载同一任务结果和离线重新转换不创建新解析任务，不重复弹出“新任务”确认，也不得暗中改成重新上传。
5. 同一工程同一时间最多一个活动云端解析任务；存在提交结果不明或尚未取得完整结果的远端任务时，禁止新建另一任务，先恢复原任务。
6. 远端失败或明确拒绝后，用户可以再次显式发起新任务；系统不自动换模型、换 endpoint 或重试上传。
7. 用户停止只停止本机等待与处理。若任务已受理，必须提示远端可能继续处理和计费；不得谎称停止本机就取消了云端任务。
8. 恢复所需的 `jobId`、provider、model 和必要的非密任务定位信息可以保存在导入记录。代理、本机路径和机器专用配置留在 `userData`；工程搬迁后若缺少原机器配置，明确限制未完成任务恢复，不自动重传。
9. 新任务固定当时的 provider、model、endpoint 和解析选项。恢复必须使用相同配置，避免把原任务结果与另一服务或模型混合。

### 3. 提交不确定性与远程恢复

任务阶段至少区分：准备、提交中、提交结果不明、查询中、下载中、转换中、已停止、失败、远端失败、候选完整。

1. 在首次 POST 前原子持久化“提交中”记录，使应用崩溃后也知道存在不确定提交。
2. POST 绝不自动重试。只有服务明确返回未受理的响应，才能把任务标为未受理失败；网络中断、超时、无效回执或可能已受理的 5xx 均进入“提交结果不明”。
3. 取得合法 `jobId` 后先持久化再查询。提交结果不明时，用户从百度控制台取得任务号并显式关联，系统不得自动再上传一次来“查找”任务。
4. 查询、下载同一结果可以使用有界网络重试，因为不会创建新解析任务；重试仍须使用原 `jobId`、服务和模型。
5. 单轮查询等待 30 分钟后可以停止本轮并提示稍后恢复，不能把远端仍在运行误报为失败或新建任务。
6. 远端明确失败时保留任务记录和诊断，要求用户检查控制台并主动决定是否新建任务。
7. 已下载结果按摘要去敏保存后，恢复不得重复下载或重复转换已完成阶段；发现摘要不符时停止并保留现场，不能静默采用另一份结果。
8. 恢复、停止、重开和工程并发写入遵守 project-core 的串行与原子提交要求；内存中的 active 状态不是唯一恢复依据。

### 4. 云端响应、资源与去敏

1. 任务状态响应必须验证 JSON 结构、任务状态和资源 URL。远端原始错误正文不直接持久化或显示，以免泄露签名参数或服务内部信息。
2. 资源下载只允许当前 endpoint origin，以及实现明确批准的百度 HTTPS 资源域名；拒绝凭据、fragment、非允许 host 和重定向。签名 URL 只在内存中用于当次下载。
3. 原始 JSONL 在写入来源快照前完成以下处理：
   - 验证页级结构、资源清单和正文块。
   - 下载或提取引用资产，验证实际字节、MIME、尺寸和摘要。
   - 将签名 URL、临时下载地址和内联大资源替换为本地内容寻址引用；无法取得的资源写成去敏占位与 warning。
4. 无法确认某个响应字段是否含凭据时，不原样持久化该字段。保留可证明安全的正文、页／块、几何和来源事实，并记录去敏原因。
5. 去敏发生在受管快照发布前；若中途崩溃，可通过原任务重新下载并重建安全快照，不把含密 staging 当作可恢复内容权威。
6. 云端图片保持原始已接受字节。PDF 页面裁剪、渲染图和消毒后的派生资产进入候选 revision，不回写原始 PDF 或解析快照。
7. 资源 URL 的允许清单、签名参数或响应内容不得进入用户可见错误、Agent 上下文或普通 Markdown。

### 5. 完整性与机器诊断

云端结果必须完成全部页面，才能进入“候选完整”：

- JSONL 页级记录完整，页数与 PDF 实际页数一致，页面尺寸和页级信息匹配。
- 非空重复页、异常页序、无效块 ID、重复块身份或非法块顺序被拒绝并保留诊断。
- 每个页面的块、公式、表格、图片和阅读顺序都有转换结果或明确诊断；不能把远端漏页当作空白页。
- 全部页面都没有形成可读正文或主要结构时，候选不可发布；个别空白／无块页面保留页级 warning，不擅自判断它是刻意空白还是识别失败。
- 图片、公式、表格、坐标等局部问题不阻塞其他已通过页面的转换，但也不被静默丢弃。

机器诊断至少区分：

- 页数与页面信息是否匹配、空页／无块页、重复页和缺失页。
- 块标签、阅读顺序、分组和层级是否为服务原值，哪些层级只能采用确定性降级。
- 公式、表格、图片和 raw block 的转换结果、占位与去敏情况。
- 坐标是否存在、页面几何是否可校准、旋转／裁剪／预处理是否使区域映射不可靠。
- 资产缺失、格式不支持、尺寸或预算失败，以及响应去敏和资源下载失败。

“检查通过”只说明上述机器项目通过，不等于文字、公式或数字与 PDF 完全一致。诊断不聚合成主观分数，也不要求 Agent 逐页审阅后才能发布。

### 6. PDF→规范文档树

1. 转换直接生成 `document.json` 与 `source-base.json` 候选；初次导入二者内容一致。不经过可编辑 Markdown 中间权威，也不把 token 流或 PDF 坐标当作正文。
2. 标题、章节、段落、列表、公式、图注、表格、脚注和参考文献映射到 document-core 的对应结构。无法可靠判断章节层级时采用较平铺的确定结构并给 warning，不让模型猜测层级。
3. vendor page／block ID 保存为 `sourceAliases`；Paper30Min 的 section／unit／sentence／atom／block ID 由 document-core 分配。页码和 vendor block ID 不能替代稳定 ID。
4. 服务提供有效 `block_order` 时保留；缺失时按页与响应数组的确定顺序降级并记录 warning。非法、重复或矛盾顺序不得静默接受。
5. 行内与独立公式保存服务返回的 LaTeX／可用结构和文本投影。识别不确定不等于可以删除；无法结构化时保留来源文本或图像占位及诊断。
6. 表格尽可能保存行、列、跨度和单元格文本。HTML 表格须消毒后转换；无法无损转换时使用有文本投影的 raw block，不只用截图代替文字。
7. 图片、图表和必要公式区域可引用云端资产或从原 PDF 生成的候选裁剪图，并保留 caption、来源页／块 alias 和可读占位。区域不可校准时只能声明页级来源。
8. 页／块几何保存在来源事实中，供 pdf-comparison 派生映射；本模块不创建 `.paper30min-citations.json`、`paper://cite` 或正式 PDF 引用关系。
9. 单页无文字但有视觉块时保留视觉块；单页无任何块时保留页级诊断。不能为了得到连续正文而删除这些事实。
10. 相同解析快照、PDF 快照和转换器版本必须产生相同规范内容；重开不重新转换、不重新分配 ID、不调用模型。

### 7. 首次发布与可读门槛

1. 首次正文可读必须等待远端全部页面返回、解析快照完整发布、全部页面转换结束以及 document-core 全量验证通过。首版不做逐页渐进 current。
2. 转换中可以报告真实页级进度并保留 staging，但部分页面不得显示为完整正文，也不得先发布空 current 冒充成功。
3. 以下情况允许带 warning 发布：个别空页／无块页、单张图片缺失、坐标仅能页级定位、个别公式／表格结构化降级，以及非核心元数据不完整。
4. 以下情况拒绝发布：缺页、页数不符、主要正文为空、重复非空页、阅读顺序破坏、规范树引用不完整、危险内容无法消毒或超出预算。
5. 警告不会自动触发二次云端任务或全文 LLM 审阅。用户可以在正文可读后选择核验、修正、原页对照或重解析。
6. revision 与元数据完整发布后，最后由 project-core 原子推进 current。 Agent 和界面随后读取同一 current，不读取另一份“Agent 专用解析稿”。

### 8. 重解析与离线重新转换

1. **重新解析**始终由用户显式发起，可以使用同一 PDF 或明确更新的新 PDF，以及当时的解析配置；每个新云端任务重新执行上传确认。
2. 同一 PDF 的新任务复用 PDF 快照但产生新解析快照。不同 PDF 产生新的父快照；二者都不能原地覆盖旧来源。
3. 新解析结果先形成候选树，再以旧 `source-base`、current 和新候选执行 document-core 三方合并。本地修正、冲突和锚点延续不由解析器直接决定。
4. **离线重新转换**复用已有解析快照和父 PDF，不访问云端、不产生新任务。转换器升级只影响新候选，不重跑新服务伪造旧 source-base。
5. 重解析或重新转换结果相同，也只能形成无正文内容变化的候选；不得因 batchId 或 revisionId 改变就让全部派生内容与核验失效。
6. 候选发布前重新核对 `baseRevision`；current 已变化时保留候选并拒绝发布。冲突解决期间旧 current 始终可读。
7. 原始 PDF 或解析快照缺失、摘要不符时，不重猜来源、不自动重新上传；当前正文仍可阅读，涉及来源的操作明确受限。

### 9. 核验记录与固定覆盖范围

核验元数据作为 revision 关联的受管侧车保存于：

```text
.paper30min/revisions/<revisionId>/verification.json
```

它不属于 document tree、source snapshot 或不可变正文内容；更新侧车不得修改 `document.json`、`source-base.json` 或来源摘要。

每条核验记录至少包含：

- 核验 ID、实际核验时的 `verifiedRevisionId`、用户请求的 DocumentAnchor，以及创建时的精确 resolved coverage。
- 覆盖节点的类型、稳定 ID、必要 sentence range、内容摘要和 quote；section 请求必须展开为当时实际包含的节点。
- PDF 快照 ID、解析快照 ID、actor、创建时间和核验方式。
- 用户核验记录显式用户确认；Agent 核验记录保存 session／task ID 和主进程来源读取证据引用。

固定覆盖规则：

1. 标记 section 只覆盖当时存在的后代节点。以后在该 section 新增的 unit／sentence 不自动成为已核验。
2. 内容不变的 retained／moved 节点保留覆盖关系；位置变化本身不制造“修改后未复核”。
3. 任何实际内容修正使相交覆盖成为 `modified-unreviewed`，保留原摘要与 quote，不把修改后的文字冒充已对照。
4. 拆分、合并或删除按 tombstone 处理，旧核验不自动挂到新节点；新增节点没有旧核验。
5. 同一范围可以重新核验，新记录指向当前 revision 和来源。文档级摘要按当前有效记录聚合，而不是永久累加历史标记。

### 10. 用户与 Agent 核验权限

1. 用户只有在明确确认“已对照此 PDF 范围”后才能建立用户核验记录。该记录表达用户声明的对照行为，不宣称应用独立证明了核验质量。
2. Agent 只有在用户明确核验任务中，实际通过主进程 PDF 来源读取工具取得对应页／区域后，才能建立 Agent 核验记录。
3. 主进程来源读取证据绑定 PDF 快照、页／区域、session／task 和实际提供的来源内容。Agent 的文本自述、普通对话、只读 current 或历史读取不能替代该证据。
4. Agent 不能直接编辑 `verification.json`；必须调用核验命令，由主进程校验锚点、coverage、来源和证据后原子写入。
5. PDF 快照不可用、证据未覆盖请求范围、current 已变化或锚点内容摘要已不符时，拒绝建立记录并保留现场。
6. 未核验正文始终可以阅读、翻译、批注和交给 Agent 讨论。任何核验状态都不是 Agent 的使用门禁。
7. 核验记录不豁免 agent-integration 对逐字引用、公式、数字和“已对照原文”等精确任务的当次来源补查要求。

### 11. 核验在重解析与 PDF 更新中的继承

发布新 current 时，按旧记录、实际 changeset 和 PDF 来源谱系生成新侧车。继承记录保留原 `verifiedRevisionId`、来源和证据，并另存当前 validity，不能改写历史使其看似已在新 revision 上完成核验：

| 变化 | 新 current 中的核验状态 |
|---|---|
| 同一 PDF 重解析，节点 retained／moved 且内容摘要不变 | 保持 `verified`，保留原解析批次和核验证据作为 provenance |
| 同一 PDF，节点内容改变 | `modified-unreviewed` |
| 不同 PDF 快照，节点内容未变 | 保留为 `historical-source`，明确尚未对照新 PDF |
| 不同 PDF 快照，节点内容同时改变 | `modified-unreviewed`，并可附来源已变化事实 |
| 节点拆分、合并、删除或无法可靠延续 | `removed`，通过 tombstone 诊断，不自动重挂 |
| 新增节点，包括加入旧已核验 section 的节点 | 无核验记录，不能继承旧 section 标记 |

- 相同 PDF 字节重新取得后复用同一 PDF 快照，不视为不同来源。
- `historical-source` 不是当前 PDF 已核验；用户或 Agent 必须实际对照新 PDF 才能建立新的 `verified` 记录。
- 文档级摘要分别呈现当前来源已核验、历史来源核验、修改后未复核和无记录范围，不合并为“全篇已审阅”或正确率。
- 旧 revision 清理前先完成新 current 的核验继承；清理失败只产生可恢复警告，不回滚新 current。

### 12. 预算与资源边界

首版沿用或收紧现有预算：

| 项目 | 上限 |
|---|---:|
| 上传 PDF | 50 MiB |
| PDF 页数 | 1–1000 页 |
| 任务状态响应 | 1 MiB |
| 受管 JSONL 下载与重建 | 256 MiB |
| facts.json | 64 MiB |
| 单页解析块 | 10,000 |
| 单个解析资产 | 32 MiB |
| 单解析快照资产合计 | 256 MiB |
| 单个 PNG 像素数 | 16,000,000 |
| 单轮远端查询等待 | 30 分钟，可恢复原任务 |

document-core 的文档树、raw block、节点数、单资产和 revision 资产预算继续适用。新树不再受旧 `candidate.md` 2 MiB 限制，但不得以删除正文方式满足预算。超限保留安全诊断与可恢复任务，不截断后报成功。

## Error and Recovery Requirements

| 情况 | 必须行为 |
|---|---|
| PDF 损坏、加密、空页、超预算或外部读取失败 | 不上传，给出具体错误，不修改外部文件 |
| PDF 在提交或转换前被替换 | 使当前任务失效并保留现场，不把结果关联到新字节 |
| POST 超时、断网、回执无效或可能已受理的 5xx | 进入提交结果不明，禁止自动重传，允许人工关联任务号 |
| 已受理任务本机停止或应用退出 | 保存 jobId 与阶段，提示远端可能继续，恢复复用原任务 |
| 远端失败、状态未知或结果 URL 不允许 | 不创建新任务，显示可行动诊断 |
| 页数不符、重复非空页、块结构损坏或正文为空 | 保留安全解析现场，拒绝发布 current |
| 图片／公式／表格局部失败或坐标不可校准 | 保留可读内容和明确 warning，不静默丢弃 |
| 响应含签名 URL、临时凭据或未知敏感字段 | 去敏后保存；无法安全处理则失败，不写含密快照 |
| 快照、候选或 revision 写入中断 | 不推进 current，按任务与摘要恢复，不猜测发布 |
| 重解析时 baseRevision 已变化 | 保留候选并拒绝发布，旧 current 继续可读 |
| Agent 无对应来源证据或证据范围不足 | 拒绝核验记录，不接受 Agent 自述替代 |
| 修改已核验正文或更换 PDF | 按实际范围标为修改后未复核／历史来源，不全篇无差别清空 |
| 工程搬迁后缺少原机器远端恢复配置 | 已保存内容继续可读；未完成任务明确受限，不自动重传 |

错误恢复不得通过删除工程、重复付费上传、自动换来源、清空诊断、伪造核验或默认采用候选来完成。

## Testing Strategy

### PDF 与来源快照

覆盖普通、加密、损坏、旋转、裁剪、混合页尺寸、扫描、空白页和超长 PDF fixtures：

- 外部 PDF 只读复制、SHA-256、页数与格式检查，原文件不被修改。
- 本地与 arXiv 固定版本来源谱系正确；不同 PDF 快照不能冒充同一字节。
- 普通参考 PDF 不进入清单，也不能未经明确更新命令替代主论文。
- 快照不可变、父级引用完整、工程搬迁后 current 与 PDF 相对路径可用。
- 页数、尺寸、旋转和预处理事实准确保留，坐标不可校准时不产生虚假区域保证。

### 云端任务与费用安全

使用受控百度 API 逐项覆盖：

- 确认前无 POST；每个新任务都确认，恢复与离线转换不创建新任务。
- POST 前崩溃、提交中断、无效回执、明确拒绝、远端失败和人工任务号关联。
- 任何提交不确定路径都不会自动重传；已有未知／未结束任务会阻止新任务。
- 查询、停止、重开、30 分钟后恢复、结果重下和已完成阶段复用。
- 恢复时 endpoint／model／PDF 摘要变化被拒绝，不混合任务。
- Token、代理、签名 URL 和原始错误响应不出现在工程、日志、IPC 错误或 Agent 上下文。
- 资源域名、重定向、响应大小和实际字节预算得到验证。

### 响应去敏与文档转换

使用完整及异常 JSONL、内联／远端图片、表格 HTML、公式和多栏页面 fixtures：

- 签名资源被本地化或去敏，正文、页／块顺序和几何事实不因去敏改变。
- 页数匹配、重复非空页、非法块 ID／顺序、空页、无块页和缺页按规定处理。
- 标题、章节、段落、公式、表格、图片、脚注和参考文献进入规范树，Agent 投影不静默缺失。
- source alias 能连接 `facts.json`，但 current 不包含正式 PDF 引用字典。
- 坐标不可校准只提供页级事实；raw block、图片占位和表格降级具有可读文本。
- 恶意 HTML、危险 URL、超像素图片和超预算块被拒绝或明确安全降级。
- 相同快照与转换器版本重复结果确定，离线重新转换无网络、无模型、无 ID 重排。

### 首次发布与重解析故障注入

分别在 PDF 复制、提交前、提交回执前、查询、下载、去敏、资产保存、解析快照发布、逐页转换、revision 发布和 current 推进前后中断：

- 工程身份与任务身份稳定，恢复不重复上传或重复发布同内容。
- 只有全部页面与完整候选通过后才显示正文可读。
- 部分解析、远端运行中和解析快照存在都不会被冒充为 current。
- 同 PDF 重解析、新 PDF 更新和离线重新转换都形成候选，执行三方合并与基线复核。
- 本地修正、冲突和旧 current 在失败时保持不变。

### 核验范围与继承

逐项覆盖：

- section 标记展开当时节点；后续新增内容不被旧记录覆盖。
- sentence range、atom、图表和跨节点范围的摘要与 quote 校验。
- retained／moved 保留，changed 标为修改后未复核，拆分／合并／删除进入 tombstone 诊断。
- 同一 PDF 重解析且内容不变保持 verified；不同 PDF 且内容不变成为 historical-source。
- 相同 PDF 字节复用不会误判为来源变化；不同 PDF 且内容改变同时表达来源与修改事实。
- 用户必须显式确认；Agent 无任务、无来源读取证据、证据页不足或 current 已变化时均被拒绝。
- 未核验正文可直接阅读和交给 Agent，不存在旧的逐页审阅 readiness 门禁。
- 文档摘要不会把历史核验、修改后未复核和无记录合并成全篇已审阅。

### 真实 Electron 高层回归

通过生产 preload、IPC、Node 工程进程、临时 PDF 和受控云服务，至少覆盖：

1. 本地 PDF 创建工程、显式上传确认、全文发布、关闭网络后重开阅读。
2. 提交结果不明、人工关联任务号、停止与重开恢复，全程无重复 POST。
3. 局部图片／坐标 warning 与缺页／空正文的不同发布结果。
4. 同 PDF 重解析、新 PDF 候选、本地修正冲突和基线变化。
5. 用户核验、Agent 来源证据核验、修改后未复核及不同 PDF 的历史来源状态。
6. arXiv 固定版本 PDF 回退的组合交接，工程和 `paper.id` 不变。
7. 工程中不出现 `materials`、旧 PDF 引用字典、`paper://cite` 或完整审阅门禁。

真实百度与代表 PDF 的发布前验收单独记录；既有 49 页审计可以帮助选择 fixtures，但不构成新实现提交的实际通过证据。

## Boundaries

### Always do

- 保留不可变 PDF 与解析快照，以 current JSON 树为唯一阅读权威。
- 在每个新云端任务前确认上传与费用，优先恢复原有 `jobId`。
- 对提交不确定性保持保守，绝不自动重传可能已受理的 PDF。
- 对全部页面执行机器完整性检查，并以来源事实和诊断说明限制。
- 将重解析做成候选，保护本地修正、稳定锚点和实际核验范围。
- 固定核验时的精确覆盖节点与来源，按 changeset 和 PDF 谱系继承状态。
- 将 Token、签名 URL、代理和机器配置挡在工程与 Agent 上下文之外。

### Ask first

- 新增云解析提供商、本地解析器、模型选项或通用 provider 抽象。
- 引入逐页渐进 current、自动重传、自动重解析、自动全文修正或 LLM 审阅门禁。
- 修改快照谱系、核验继承、预算、资源域名或凭据持久化边界。
- 恢复正式 PDF 引用字典、可编辑 Markdown 正文权威或 `materials` 登记。
- 删除 PDF／解析快照、核验记录或无法确认归属的恢复现场。

### Never do

- 把 PDF 页码、文件哈希、vendor block ID 或坐标字典当作论文／正文身份。
- 未经确认上传 PDF，或在提交结果不明时自动再上传一次。
- 将停止本机等待说成取消远端任务，或对远端失败自动换配置重试。
- 把原始签名 URL、Token、代理凭据或机器专用配置写入工程。
- 把部分页面、空正文或只有摘要的结果显示为完整可读正文。
- 要求完整 LLM 审阅后才能阅读、翻译、批注或使用 Agent。
- 用主观质量分数、“全篇已审阅”或历史核验冒充当前来源实际核验。
- 让 Agent 仅凭自述写入核验，或把新增／修改内容自动纳入旧核验范围。
- 原地修改快照、静默覆盖 current，或用 PDF 重解析丢弃本地修正。

## Success Criteria

- [ ] 本地与 arXiv 固定版本 PDF 均形成不可变来源谱系，PDF 哈希不替代工程或论文身份。
- [ ] 每个新云端任务均有显式确认；提交不确定与恢复测试证明不会自动重复上传。
- [ ] Token、签名 URL、代理和机器配置不进入工程、日志、revision 或 Agent 上下文。
- [ ] 全部页面完成后才发布 current；局部保真问题有诊断，缺页和空正文不能冒充完整正文。
- [ ] PDF 解析结果直接进入规范文档树，界面与 Agent 读取同一 current，无独立 Markdown／Agent 正文。
- [ ] 未完整 LLM 审阅的 PDF 解析稿可离线阅读和使用后续 Agent 能力，无逐页审阅门禁。
- [ ] 同 PDF 重解析、新 PDF 更新和离线重新转换均形成候选，遵守三方合并与 `baseRevision`。
- [ ] 核验固定当时覆盖范围，Agent 记录具有主进程来源证据，新增内容不自动继承。
- [ ] 同 PDF 内容不变可保留核验；不同 PDF 显示历史来源；修改、拆分和删除按规定失效。
- [ ] 文档摘要区分当前来源核验、历史来源、修改后未复核和无记录，不产生主观质量分数。
- [ ] 新工程不出现 `materials`、旧 PDF 引用字典或 `paper://cite`。
- [ ] `npm run typecheck`、`npm run build` 和适用 Windows Electron 回归在实现提交上实际通过；真实百度证据单独记录。

## Open Questions

本模块没有阻塞批准的产品开放问题。以下事项由对应规格继续定义：

- Agent 如何发起来源读取、精确任务补查和核验任务：`agent-integration`。
- 正文与 PDF 的 unit→页／区域映射、双向同步和降级展示：`pdf-comparison`。
- 原页、诊断和核验范围的具体视觉布局：`reader`、`workspace`。
- 旧解析批次、引用和审阅记录如何处理：`legacy-projects`。
