# Spec: workspace

> 状态：已批准  
> 所属能力地图：[文本中心阅读核](capability-map.md)  
> 依赖：[reader](SPEC-reader.md)、[annotations-results](SPEC-annotations-results.md)（均已批准）  
> 协同：[translation](SPEC-translation.md)（已批准）  
> 下游：`agent-integration`、`pdf-comparison`

## Objective

为 Paper30Min 提供最多左右两个中栏窗格的工作区。每个窗格拥有独立页签条、活动页面、阅读位置和编辑视图状态；原文、PDF、笔记、精解、记忆卡片和其他中栏页面都能并排，而不是只允许 PDF／原文这一种组合。

普通打开进入当前窗格并优先复用已有页签；「侧边打开」进入或创建另一窗格并聚焦新页面。只有显式“在新视图中打开”才创建同文档副本。标签拖拽支持分栏、窗格内重排和跨窗格移动，不扩展为自由多栏或上下网格。

布局、页签实例、阅读位置和未发布草稿保存在工程内受管 workspace 区域，随工程整体搬迁。窗口尺寸、左右应用侧栏与 Agent 宽度等本机偏好仍保存在 Electron `userData`，不混入工程内容权威。

本模块成功时，应满足：

- 任意两个中栏页面都能并排，两个窗格互不覆盖活动页、滚动、光标、语言或编辑视图状态。
- 普通打开不会误建副本；同文档显式副本可以分别阅读不同语言或位置，Markdown 草稿内容仍保持同源。
- 拖拽和关闭页签不会静默丢弃草稿、制造重复页签或留下无所有权的空窗格。
- 重开、崩溃、工程搬迁和文件缺失时保留可恢复现场，不按路径失效直接丢弃页签。
- 右侧 Agent 独立于中栏双窗格，PDF 语义同步只在兼容页面组合上注册。

## Scope

### In scope

- 最多两个中栏窗格、独立页签组、活动页签和当前窗格。
- 页面描述、页签实例 ID、普通打开、侧边打开和显式重复视图。
- 窗格内重排、跨窗格移动、拖拽分栏、合并与空窗格收尾。
- 分隔条调整、窄窗口行为、键盘与菜单等价操作。
- 原文、PDF、Markdown 及其他中栏页面的独立视图状态。
- 同 Markdown 多视图的内容同步与独立光标／滚动／模式。
- 工程内布局、未发布草稿、冲突解决现场和恢复记录。
- 文件缺失、外部修改、多进程写入、工程搬迁和旧状态分流。
- 成果卡片的默认侧边打开偏好及当前／侧边两种入口。
- 右侧 Agent 独立性和 PDF 同步页面配对宿主。

### Out of scope

- 正文、PDF、Markdown 编辑器及侧栏卡片本身的实现，属于对应模块。
- Agent 会话、工具和右侧交互，属于 `agent-integration`。
- PDF unit→页／区域映射与双向同步，属于 `pdf-comparison`。
- 自由多栏、上下网格、浮动窗口、通用 IDE 停靠布局和多窗口管理。
- 普通文件移动、Markdown 保存算法、正文 revision 提交和来源任务。
- 应用窗口尺寸、最近工程、默认目录、Agent 宽度等本机偏好结构。
- 旧 `.paper30min-reading.json` 的实际迁移，属于 `legacy-projects`。

## Tech Stack

- React、TypeScript、Electron 主进程／Node utility process 和受限 IPC／preload。
- 工程内 JSON 保存布局与恢复草稿；同目录临时文件、同步与原子替换。
- 沿用现有 Markdown 草稿、PDF 位置、reader 锚点和 changeset 宿主接口。
- Pointer Events／键盘实现标签拖拽与分隔条；不引入通用停靠布局框架。
- 每个异步视图操作用 projectId＋paneId＋tabInstanceId＋epoch 隔离，防止迟到结果写错页面。
- 不使用 SQLite，不把 workspace 状态登记进 `paper30min.json` 清单，不保存模型或解析凭据。

## Commands

在仓库的 `app/` 目录执行：

```powershell
npm ci
npm run typecheck
npm run build
npm test
```

针对本模块的真实 Electron、布局与恢复回归：

```powershell
npx playwright test -g 'workspace'
```

默认使用临时工程、普通 Markdown、原文和 PDF fixtures，不访问真实模型或来源服务。隐藏窗口回归仍须验证真实页签、拖拽、焦点、草稿、截图和重开；原生拖放、系统焦点或人工视觉验收需要单独记录实际窗口证据。

## Project Structure

### 仓库代码边界

```text
app/src/renderer/workspace/  窗格、页签、拖拽、当前焦点和视图宿主
app/src/main/workspace/      布局、恢复草稿、冲突和迁移持久化
app/src/shared/workspace/    页面、页签实例、布局和 IPC 类型
app/tests/fixtures/workspace/  多页面、草稿、缺失文件和冲突 fixtures
app/tests/                   打开目标、拖拽、恢复和真实 Electron 回归
```

现有 `App.tsx` 的单页签组、`usePanelLayout.ts` 的宽度交互，以及 `useMarkdownDocuments.ts` 的草稿能力是改造输入。旧 `saveWorkspace` 的单 `active` 和按文件路径过滤恢复不能满足双窗格；这些假设可以删除，不要求保留兼容字段。

### 工程内 workspace 契约

```text
.paper30min/workspace/
  current.json              # projectId、当前恢复 session 与指针版本
  sessions/<sessionId>/
    layout.json             # 窗格、页签实例、活动状态和视图状态
    drafts/                 # 未发布内容的受管恢复记录
```

- `sessionId` 标识一次应用实例／恢复现场，避免两个进程共享同一可写文件。`current.json` 只指向最后明确登记的恢复 session，不是正文权威。
- `layout.json` 保存 `projectId`、窗格、页签实例、活动窗格、活动页签、分隔比例、普通文件版本和原文 baseRevision 等恢复事实。
- 普通 Markdown 的共享草稿按规范化路径保存；同文件的多个页签实例只在 layout 中保存各自光标、滚动和模式。原文修正、冲突解决等实例草稿按 tabInstanceId 保存。
- 恢复草稿记录预期普通文件版本／baseRevision、实际未发布内容、更新时间和冲突状态。普通文件保存成功后，其内容权威回到普通文件，恢复记录可以原子清理。
- `current.json` 与 session 文件分别原子提交；先完整保存 session，再推进恢复指针。未登记 session 不得按时间或文件名猜测为当前恢复目标。
- workspace 区域不参与普通成果扫描，不预建空目录，不保存 API key、代理、模型配置或机器专用路径。
- 只保留当前恢复所需 session 和明确冲突现场。清理由本应用所有权和引用关系决定，不按时间删除未知 session。

## Code Style

页签实例与页面身份分离：

```ts
export interface PageDescriptor {
  pageKey: string;
  kind: "reader" | "pdf" | "markdown" | "source-status" | "other";
  title: string;
}

export interface TabInstance {
  id: string;
  page: PageDescriptor;
  viewState: unknown;
}

export interface WorkspaceLayout {
  formatVersion: 1;
  projectId: string;
  sessionId: string;
  panes: WorkspacePane[];
  activePaneId: string;
  splitRatio: number;
}
```

- `pageKey` 是同文档去重键，`tabInstanceId` 是具体视图实例；两者不能混用。pageKey 使用稳定的受管来源／普通相对路径，不使用绝对路径。
- `panes` 长度为 1 或 2，每个 pane 有稳定 paneId、独立 tabs 和 activeTabId；不保存第三个中栏。
- `viewState` 由对应页面 schema 验证，包含阅读位置、语言、光标、模式等，不把可执行对象、DOM 或 EditorState 直接序列化。
- `splitRatio` 是左右窗格比例，恢复时按实际窗口与最小宽度约束校正，不保存机器窗口尺寸。
- Node ESM 相对导入沿用 `.js` 后缀，共享类型不得导入 Node 或 React 模块。

## Behavior Contract

### 1. 页面与页签实例

1. 所有可进入中栏的页面必须有 PageDescriptor 和页面专属视图 schema。原文、PDF、Markdown、来源状态等都可以进入任一窗格。
2. `pageKey` 在同一工程内稳定：主论文 reader 使用 paperId，PDF 使用来源快照谱系，普通 Markdown 使用规范化相对路径，其他页面使用明确受管 key。
3. 每次打开页签实例分配持久 UUID。显式副本具有不同 tabInstanceId，但可共享同一 pageKey。
4. 页签标题显示文档标题；同 pageKey 多实例增加语言／视图或序号等可辨识信息，不靠不同路径伪装副本。
5. 每个实例独立保存阅读位置、语言、PDF 页面状态、Markdown 光标／模式、原文修正草稿和冲突视图状态。
6. 页面不存在或来源缺失时保留页签实例、标题、路径和最后状态，显示可行动占位；不能像旧实现一样在恢复时静默过滤掉。
7. 页面 kind 或 viewState 版本无法识别时，保留原始 descriptor 到恢复现场并报告不兼容，不丢弃用户草稿。

### 2. 当前窗格与普通打开

1. 单窗格时它始终是当前窗格；双窗格时，最近一次点击、键盘聚焦、页签激活或拖拽落点所属窗格成为当前窗格。
2. 每个窗格保留自己的 activeTabId。当前窗格变化只改变焦点，不改变另一窗格的活动页面或滚动位置。
3. 普通打开先在当前窗格、再在所有窗格查找目标：
   - pageKey 未打开时，在当前窗格新建页签并激活。
   - pageKey 已打开时，激活最合理的既有实例，不创建副本；有多个实例时优先当前窗格，其次最近活动实例。
4. 普通打开不得移动另一窗格的既有页签，也不得为了激活目标而重置其语言、滚动或草稿。
5. 当前窗格通过明确的焦点样式和非颜色语义标识；右侧 Agent 或文件树焦点变化不得暗中改变中栏活动页签。

### 3. 侧边打开与显式副本

1. 「侧边打开」以发起操作的窗格为来源：单窗格时创建第二窗格，双窗格时以另一窗格为目标。
2. 目标 pageKey 在另一窗格已存在时，激活该实例而不复制；仅在其他位置存在时，激活既有实例，不为了符合方向而复制或移动。
3. 如果用户明确要同文档并排，使用“在新视图中打开”：
   - 在另一窗格创建新的 tabInstanceId 并激活。
   - 原文实例可以独立选择 source／translation，实现不同语言或不同位置并读。
   - Markdown 实例共享同一份文件草稿，但滚动、光标和 read／edit／split 模式独立。
4. 侧边打开和显式副本完成后，目标页签成为目标窗格活动页，并把键盘焦点交给目标窗格；来源窗格的活动页和阅读位置保持不变。
5. 显式副本不是拖拽的默认行为，普通点击也不会隐式创建副本。
6. 笔记、精解等成果卡片始终提供“当前窗格打开”和“侧边打开”两种入口；偏好只改变主按钮默认行为，不取消另一种入口。
7. 支持按成果类型保存默认打开目标，至少覆盖笔记和精解；未配置类型默认当前窗格。偏好保存在应用设置中，不写工程清单。
8. 打开动作发生保存失败、目标解析失败或草稿冲突时，保留来源与目标现状，不先关闭来源页签。

### 4. 标签拖拽与窗格收尾

1. 拖到同一页签条的新位置只重排，不改变 tabInstanceId 或视图状态。
2. 拖到另一窗格的页签条或内容区域是**移动**，不是复制；活动页、语言、滚动和草稿引用随实例迁移。
3. 单窗格时，拖到明确的左侧／右侧分栏投放区创建第二窗格；普通页签条内拖拽不意外分栏。
4. 投放预览明确区分重排、移动和分栏。Esc、pointer cancel、窗口失焦或非法目标取消操作并保持原布局。
5. 移动最后一个页签离开一个窗格后，该空窗格被移除，另一窗格成为唯一当前窗格；不保留无所有权的空白第二栏。
6. 关闭某窗格最后一个页签采用相同收尾；关闭全部页签后显示工程中立的空工作区，不伪造主论文已打开。
7. 拖拽过程中不得保存半成品布局。完成投放后才原子更新 session；取消或写入失败时恢复投放前布局。
8. 提供“移到另一窗格”“在侧边打开”“重排到最前／最后”等键盘／菜单等价操作，拖拽不是唯一入口。
9. 分栏比例通过分隔条调整并持久化，键盘方向键也可操作；比例受限，不能将任一侧压缩到不可用宽度。
10. 窄窗口只改变实际 CSS 布局，不销毁第二窗格或页签。reader 按各自容器宽度切换边栏／内联。

### 5. 同文档多视图状态

1. 同 pageKey 多实例的 reader 位置、语言、selection 和原文修正草稿独立；底层 current 文档树和来源快照仍只有一份。
2. 同一路径 Markdown 使用同一个草稿内容与磁盘基线：
   - 任一视图的编辑同步到另一视图，不形成两份互相覆盖的文本。
   - 光标、选择、滚动、read／edit／split 模式和 IME 会话保持独立。
   - 外部修改／保存冲突在两个视图中一致呈现，但用户可分别查看双方内容。
3. 同步另一视图时不得重写其 EditorState、打断 composition、移动光标或跳回其正在阅读的位置。
4. 同文件保存成功后，所有实例共享新文件版本；恢复草稿同步清理，视图状态保留。
5. 原文两个修正草稿可以指向不同操作或目标，但发布时都重新检查 baseRevision；一个发布后另一个必须保留并按新基线提示处理。
6. 原生批注、成果卡片和翻译更新可以同步到所有实例，但每个实例的异步渲染与恢复 epoch 独立。
7. 页签移动和关闭只改变实例归属，不复制普通文件内容或产生新的成果身份。
8. 普通文件移动／改名后，按新相对路径重定向 pageKey 与共享草稿，保留 tabInstanceId 和视图状态；不能关闭旧页签后另建副本，也不提供材料式 relink。

### 6. 草稿与关闭保护

1. 普通 Markdown 继续沿用内容基线、自动保存和外部冲突检测；workspace 恢复草稿不是另建自动保存通道，也不绕过冲突。
2. 原文修正、候选冲突解决和其他未发布操作以受管恢复草稿保存，明确其 baseRevision 与实例归属。
3. 关闭有未发布内容的页签时，用户可以选择：
   - 保留恢复草稿并关闭，之后从恢复入口继续。
   - 取消关闭。
   - 明确丢弃该实例未发布内容。
4. 默认安全动作是保留草稿，不因关闭页签、窗格或应用而静默丢弃。普通 Markdown 已成功保存到普通文件的内容不算未发布草稿。
5. 丢弃必须针对明确实例和内容，不能一键清除同文件其他实例、来源快照或普通成果。
6. 应用退出、窗口重载和崩溃前先提交当前 session 与恢复草稿；未能完成时保留上次完整提交，不写半个 JSON。
7. 恢复草稿中的普通文件版本／baseRevision 已变化时，恢复内容并标冲突，要求重新读取或合并，不直接保存或发布。
8. 自动保存失败、系统关闭中断或恢复记录损坏时，保留旧记录和用户输入，提供导出／复制恢复内容的途径。

### 7. 布局与恢复提交

1. 布局变更采用防抖提交，但页签关闭、拖拽完成、草稿更新、应用隐藏和退出等边界必须显式 flush。
2. 每次提交先写入完整 session 文件并验证，再以内容基线原子推进 `current.json`；指针是最后一步。
3. `current.json` 记录 projectId、sessionId 和指针版本。推进前发现指针已被另一进程改变时，不覆盖它，保留自己的 session 为冲突恢复现场并提示。
4. 两个应用实例使用不同 sessionId；不得通过 last-write-wins 合并两个布局或草稿。恢复时由用户选择明确 session。
5. 恢复时验证 projectId、schema、tabInstanceId 唯一性、pane 数量、活动引用、相对路径和 viewState。无效部分保留原始数据供诊断，不静默重排成另一布局。
6. 普通文件缺失时保留页签和恢复草稿；用户可将文件放回原路径、手动打开新位置或关闭页签。普通文件不提供材料式 relink 身份。
7. 主论文 current 已变化时，页签继续属于同一 paperId，阅读位置按 reader changeset 规则恢复，修正草稿按 baseRevision 冲突处理。
8. 工程整体复制或移动后，projectId、pageKey、相对路径和 session 仍按新根目录工作；userData 的最近工程与窗口偏好不随工程迁移。
9. 旧 `.paper30min-reading.json` 只由 legacy-projects 决定迁移／只读／拒绝；本模块不猜测转换。

### 8. 右侧 Agent 与页面配对

1. 右侧 Agent 是独立应用侧栏，可展开／收起，不计入两个中栏窗格，也不参与中栏标签拖拽。
2. Agent 的宽度、展开状态等本机偏好保存在 userData；Pi 会话继续保存在工程 `.pi/sessions/`，不由 workspace layout 复制。
3. 打开侧边成果、切换当前窗格或关闭中栏页签不自动关闭 Agent、切换会话或清空输入草稿。
4. workspace 向 agent-integration 提供当前窗格、活动页签和显式选区事件。已经附加到对话的来源不因焦点变化被静默替换。
5. workspace 只暴露当前页面组合和来源谱系，供 pdf-comparison 注册兼容配对：
   - 主论文结构化 reader 与其来源 PDF。
   - 同 pageKey 的 reader 副本可与同一 PDF 配对，但各自同步状态独立。
6. 笔记｜笔记、精解｜笔记、Markdown｜PDF 等组合可以并排，但不提供语义同步；不得根据文本相似度自行建立同步关系。
7. 页面切换、移动或关闭后，旧配对的异步定位不得应用到新组合。

### 9. 异步与焦点安全

1. 所有打开、关闭、恢复、拖拽和视图加载操作使用导航 epoch；工程、pane、tabInstance 或活动目标变化后，旧操作不能提交到新布局。
2. 页签切换前先完成必要的草稿与位置捕获，但不得用异步保存结果覆盖用户在新页签中的操作。
3. 工程切换时取消旧工程未完成的打开与恢复，旧工程的卸载 flush 只能写旧 session。
4. 多实例同页渲染不能因为 pageKey 相同而共享可变 DOM、selection、PDF viewer 或异步任务。
5. 当前焦点和键盘目标在拖拽、分栏、关闭、恢复后都有明确落点；不得焦点落到已卸载按钮或不可见窗格。
6. 普通外部文件变化、来源更新和卡片更新不得在没有用户操作时突然抢焦点或改变当前窗格。

## Error and Recovery Requirements

| 情况 | 必须行为 |
|---|---|
| 普通打开已存在 pageKey | 激活既有实例，不重复创建，不重置视图状态 |
| 显式副本同文档 | 新 tabInstanceId，共享内容权威，独立视图状态 |
| 拖拽取消、非法落点或写入失败 | 保留原布局和草稿，不留下半完成分栏 |
| 移动／关闭最后页签 | 移除空窗格并明确焦点，不保留空白第二栏 |
| 关闭未发布内容 | 默认保留恢复草稿，取消或明确丢弃才改变现场 |
| session 完整、current 指针未推进 | 不把新 session 当当前恢复目标，旧指针继续有效 |
| 两进程同时修改恢复指针 | 各自保留 session，提示冲突，不 last-write-wins |
| 普通文件缺失／外部变化 | 保留页签和草稿，标冲突，不静默丢弃或覆盖 |
| baseRevision 已变化 | 恢复修正内容并要求重新处理，不直接发布 |
| 工程搬迁 | 按 projectId 与相对路径恢复，userData 偏好不混入 |
| 页面 schema 不支持 | 保留 descriptor 与草稿并报告，不静默删除 |
| 旧异步打开／恢复结果迟到 | 丢弃对新布局的应用，不覆盖用户当前操作 |

错误恢复不得通过过滤掉缺失页签、复制两份草稿、合并冲突 session、默认丢弃未发布内容或重载整个工程来完成。

## Testing Strategy

### 打开目标与重复视图

- 单／双窗格的普通打开、侧边打开、显式副本和已有实例激活。
- 有多个同 pageKey 实例时按当前／最近活动规则选择，不随机跳页。
- 侧边打开后焦点到目标，来源活动页与阅读位置不变。
- 原文副本独立语言与滚动；Markdown 副本共享内容、独立光标／模式／IME。
- 成果卡片当前／侧边入口和按类型默认偏好。
- 打开失败不关闭来源页签或清空目标草稿。

### 拖拽与窗格生命周期

覆盖同栏重排、跨栏移动、拖出分栏、拖回合并、取消和非法目标：

- tabInstanceId 与视图状态保持，非显式操作不复制。
- 最后一个页签移动／关闭后空栏消失，活动窗格和焦点正确。
- 分隔条拖动、键盘、比例约束和窄窗口不会销毁第二栏。
- 拖拽途中崩溃或写入失败只留下完整旧布局。
- 菜单与键盘能完成所有拖拽等价操作。

### 草稿、关闭与多视图同步

- 普通 Markdown 自动保存、外部冲突、同文件两视图编辑同步和独立光标。
- 同步更新不重置另一视图 EditorState、composition 或滚动。
- 原文修正两实例基线变化、保留与重新处理。
- 关闭页签／窗格／应用时保留、取消、明确丢弃分支。
- 恢复草稿损坏、普通文件版本变化和导出恢复内容。
- 保存成功后恢复记录清理不影响视图状态。

### 布局恢复与故障注入

分别在布局写入、草稿写入、session 完成、current 指针推进和恢复加载阶段中断：

- 未登记 session 不按时间猜测，旧 current 保持可恢复。
- 两进程指针冲突保留双方，不合并布局或草稿。
- projectId、tabInstanceId、活动引用和 viewState 校验失败保留原始现场。
- 文件缺失、来源更新、工程整体搬迁和 schema 不支持不静默丢页签。
- 快速切换工程／页签／窗格时，旧异步结果不覆盖新布局。

### 真实 Electron 与视觉交互回归

通过生产 preload、IPC、真实临时工程和多类型页面验证：

1. 原文｜PDF、原文｜译文、原文｜笔记、精解｜笔记、笔记｜笔记组合。
2. 独立页签条、活动页、滚动、光标、语言、编辑模式和右侧 Agent 收起。
3. 拖拽分栏、跨栏移动、重排、关闭与焦点恢复，附实际截图。
4. 同 Markdown 双视图编辑、外部冲突、关闭保留和重开恢复。
5. 崩溃恢复、多进程指针冲突、缺失文件和工程搬迁。
6. 兼容 PDF 配对注册与非兼容组合无误同步；旧配对异步结果不串页。

涉及原生拖放、系统焦点、IME 或人工视觉判断的用例单独记录实际窗口证据，不能只凭状态对象断言记为全部交互通过。

## Boundaries

### Always do

- 保持最多两个中栏窗格和各自独立页签组、活动页与视图状态。
- 普通打开去重，只有显式命令创建同文档副本。
- 侧边打开聚焦目标，保留来源窗格状态。
- 将布局与未发布草稿保存在工程内受管 workspace，按相对路径搬迁。
- 用完整 session＋原子指针、内容基线和实例 ID 保护恢复。
- 保留缺失文件、冲突和未知页面的现场，用真实 Electron 验证交互。

### Ask first

- 增加第三窗格、上下网格、浮动停靠、多窗口或通用 IDE 布局框架。
- 让侧边打开默认复制、拖拽复制或同文件生成两份独立文本草稿。
- 修改 workspace 磁盘协议、恢复指针、去重键或草稿丢弃政策。
- 将窗口偏好、凭据、Agent 会话副本或成果身份写入 workspace。
- 引入自动迁移旧 reading 状态、静默 relink 或相似度页面同步。

### Never do

- 因文件缺失、schema 未知或工程搬迁直接过滤掉页签和草稿。
- 让同 Markdown 多视图互相覆盖文本、光标、IME 或滚动。
- 让普通打开、侧边打开或拖拽隐式创建重复实例。
- 用 last-write-wins 合并多进程布局，或按时间猜测恢复 session。
- 在拖拽完成、冲突解决或发布前把中间状态提交为最终布局／正文。
- 将右侧 Agent 算作第三个中栏，或让焦点变化替换已附加对话来源。
- 给非兼容页面组合提供相似度同步，或让旧异步结果应用到新页面。
- 把凭据、绝对机器路径或本机窗口配置写入工程 workspace。

## Success Criteria

- [ ] 任意两个中栏页面可并排，每栏独立页签、活动页、阅读位置和编辑视图状态。
- [ ] 普通打开与侧边打开按 pageKey 去重，显式副本按 tabInstanceId 独立，侧边焦点正确。
- [ ] 原文副本可独立选择语言，Markdown 副本共享文本但不互相重置光标、模式或 IME。
- [ ] 拖拽分栏、重排、跨栏移动和空栏收尾均无隐式复制、半成品布局或焦点丢失。
- [ ] 未发布内容关闭时默认保留恢复草稿，明确丢弃不会波及其他实例或成果。
- [ ] session 完整提交后才推进 current 指针，多进程冲突不覆盖双方现场。
- [ ] 文件缺失、外部修改、baseRevision 变化和未知 schema 均保留可恢复页签与草稿。
- [ ] 工程整体搬迁后布局、页签、相对路径和恢复记录继续工作。
- [ ] 右侧 Agent 独立，PDF 同步只在兼容组合注册，非兼容页面不会误同步。
- [ ] `npm run typecheck`、`npm run build` 和适用 Windows Electron／视觉交互回归在实现提交上实际通过。

## Open Questions

本模块没有阻塞批准的产品开放问题。以下事项由对应规格继续定义：

- Agent 如何消费当前窗格、选区和显式附件：`agent-integration`。
- 兼容原文＋PDF 组合的同步定位：`pdf-comparison`。
- 旧单页签 reading 状态的迁移、只读或拒绝：`legacy-projects`。
