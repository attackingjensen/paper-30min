# Paper30Min v1.4.0

正式版于 2026-10-11 [发布](https://github.com/attackingjensen/paper-30min/releases/tag/v1.4.0)。版本 [PR #108](https://github.com/attackingjensen/paper-30min/pull/108) 已合并，正式包从 `main` 的 `d090e524bc16c1029ad74bd039697aec649acc99` 构建，`v1.4.0` 标签指向同一提交。

## 本版变化

- 在设置页选择本地解析或百度 AI Studio 云端解析。云端解析使用用户自己的凭据，上传前确认费用；导入后自动取回、转换正文与来源、准备离线视觉资源并发布，无需逐步点击内部阶段。
- 已受理的云端任务保存本机记录，支持恢复查询与取回；取消不保证远端停止计费，重新提交需再次确认，不自动付费重传。
- 发布时校验完整候选批次。重新解析成功后替换当前结果，失败或取消保留旧结果；历史产物保留原批次依赖，整库导出导入携带这些资源，旧引用不会误绑新正文。
- 修复建图并发进度倒序、窄窗口横向溢出、保留书库卸载后的重新安装，以及连续缩放后 PDF 重绘不收敛。限制画布像素分配并释放页面资源，统一阅读页顶部操作栏样式。

主程序版本为 1.4.0，书库 schema 为 9；应用标识与更新器公钥不变。本地解析组件继续使用 [v1.2.0-beta.1](https://github.com/attackingjensen/paper-30min/releases/tag/v1.2.0-beta.1)，本版不重新生成或上传组件包。本地组件瘦身、多厂商解析和 GPU 策略重写留待后续版本。

## 验收证据

- JavaScript `node --test`：320 项通过。完整 `cargo test --offline` 通过，默认忽略项未当作通过；`npm run smoke`：14 项通过。
- `node tests/integration/cloudparse-webview.mjs`：14 项通过。覆盖设置、解析服务选择、上传确认、恢复、导入竞争及离线来源；其中出站请求和对话框使用替代，不当作真实供应商验收。
- 复用 U3-U6、整改与阅读修复的单元三轴审查，最终补查跨任务整合，未发现新增代码问题。发布元数据另行核对，三处版本一致。
- 安装版 PDF 复核：长文、混合尺寸和 300 DPI 页面共 9 个滚动与连续缩放阶段全部收敛，像素与尺寸检查通过；阅读操作栏原生布局 5 项通过。测试安装身份及源码覆盖范围保留在本机报告，不等同于最终正式包走查。
- 用户实际操作内存采样：工作集峰值约 843 MiB，结束约 732 MiB；私有内存峰值约 556 MiB，结束约 441 MiB。该观察显示短时回收，不证明长期无泄漏，也不推断正式包必然更省内存。
- 获准新增上传不超过 50 页，实际上传 12 页：Turing 扫描件前 6 页、自制跨页表格 2 页、ResNet 前 2 页的 300 DPI 无压缩扫描 PDF（48.15 MiB），以及旋转/CropBox 边界 2 页。前三项自动完成取回、视觉准备与发布；边界任务发现浮点尺寸导致视觉准备失败，修复后复用原 job 恢复发布，未重复上传。
- 扫描件与大文件按原 PDF 核对逐页首尾内容及来源框，未见同尺寸页语义换位；控制表格 R01-R20、计数 101-120、分数 0.51-0.70 各出现一次且归属正确页面。供应商将跨页表格保留为两张表，不承诺自动合并。旋转/CropBox 样本保留页级来源与整页视觉资源，不产生未经验证的精确来源框。
- 48.15 MiB 文件处理采样的进程组工作集峰值约 2.86 GiB，结束约 1.06 GiB；结束私有内存约 1.73 GiB。该开发验收包含自动化文件传输及本地组件预热，不能直接代表正式包基线；未观察到内存不足，但接近上传上限的文件仍可能造成较高临时内存占用。
- 隔离 Release 原生宿主确认本地组件不可用，三份真实云端已发布批次重启后仍可读，PDF 画布非空；使用本机 SSE 模型夹具完成建图、精读、携带视觉证据、引用打开原 PDF 及重载后产物保留。四项检查通过。浏览器出站请求仅允许本机，未读取或调用真实聊天凭据；这证明离线资源与原生协议衔接，不代替模型质量评估或正式安装包走查。

- 本次近上限专项覆盖文件大小，长篇页数压力复用既有 150 页样本证据。OCR 的局部误差仍存在，不将上传成功等同于内容完全准确。
