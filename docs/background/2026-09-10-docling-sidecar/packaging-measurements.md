# Docling 侧车打包体积与速度复核（#57 验收项 3）

- 日期：2026-09-10
- 票据：[#57 Docling 侧车打包与进程契约](https://github.com/attackingjensen/paper-30min/issues/57)
- 基线：[#46 实测](2026-09-09-harness-validation/docling-sidecar-validation.md)（同一台机器：i5-13500H / 32GB / Win11 x64）
- 判据：打包体积与速度均不超 #46 实测基线的 1.5 倍。

## 体积复核（随包案 = 默认）

| 项 | #46 估算 | 本票实测 | 判定 |
| --- | --- | --- | --- |
| 侧车落盘（嵌入式 Python 3.11.9 + 钉版依赖 + 模型） | 约 1.5GB | **1504MB**（`sidecar-manifest.json`：1,576,869,467 字节） | ✅ |
| 安装包增量（压缩后） | +0.8–1.0GB | **NSIS 安装包整体 728MB**（`Paper30min_0.1.0_x64-setup.exe`，应用本体约 15MB，即增量约 710MB；deflate/zip 代理复测 856MB 为同量级旁证） | ✅ |
| 首启下载案安装包增量 | 约 50MB | **36MB**（Python 嵌入包 + 下载器 + 声明） | ✅ |
| 首启下载量 | 约 0.9GB | 依赖 322MB（wheel 压缩包）+ 模型 537MB ≈ **0.86GB**（实测下载走通） | ✅ |

精简手段（相对 #46 venv 的 1.5GB site-packages）：去 `__pycache__`/`*.pyc`/包内 tests 目录/torch `include`+`share`；
依赖不做人工裁剪（保持与 #46 验证环境逐版一致，105 个钉版包，`requirements-sidecar.txt`）。

## 速度复核（热态，秒/页）

方法与 #46 的差异：#46 单进程连跑 10 篇（模型加载摊薄）；本票为进程级契约（每次导入一个子进程，
含 Python 启动 + torch/docling 导入 + 模型加载约 15–20s 固定开销）。同日下午同机用 #46 venv
以同一侧车协议跑对照（排除机器状态干扰）。

| 论文（页数） | #46 基线 s/页 | 侧车实测 s/页 | 倍率 | 判定（≤1.5×） |
| --- | --- | --- | --- | --- |
| 1610.00633（9） | 4.0 | 2.5（22.4s） | 0.63 | ✅ |
| 1706.03762（15） | 4.7 | 2.9（43.7s） | 0.62 | ✅ |
| 1810.04805（16） | 4.1 | 2.9（45.6s） | 0.69 | ✅ |
| 2106.09685（26） | 6.8 | 7.8（203.6s） | 1.15 | ✅ |

同协议 venv 对照：1610 同脚本同模型 22.7s（侧车 22.4s）——嵌入式 Python 无性能损耗。

**过程中发现并修复的规格级问题**：Docling 默认 `OcrAutoOptions` 会对文本层论文的插图位图区域
逐页 OCR（CPU 上每页 12–50s，#46 快是因为该路径当日未被有效触发）。按 #48 决策 1
"OCR 仅对无文本层页触发"加了预扫门禁（`do_ocr = 存在无文本层页`），这也是上表三篇快于基线的原因。

## 冷启动说明

构建产物目录首次被逐文件读取时，Windows Defender 实时扫描会拖慢首个转换（观测 85–110s/9 页）；
文件缓存热后恢复上表数值。真实安装场景（NSIS 解包）同理会有一次性首跑成本，属已知系统行为。

## 首启下载案端到端验证

download 变体（36MB）经 `bootstrap` 子命令完整补齐：get-pip 引导 → pip 安装 105 个钉版包
（本机复测用 wheel 缓存离线安装）→ 模型下载（干净 HF_HOME 下官方源失败、自动回退
hf-mirror 实下 537MB；RapidOCR 模型走 docling 自带下载器的 modelscope 源，国内可达、
不受 HF_ENDPOINT 管辖）→ convert 冒烟通过。HF_ENDPOINT 可经 `settings.putPdfparse@1`
或任务输入 `endpoint` 覆盖。

## 留档结论

体积与速度两子项均在 #46 基线 1.5 倍内，验收通过。回归门禁（踩坑论文集断言）归 #60；
性能基线的机器状态敏感性（同日 venv 复测曾差 1.7×）提示 #60 的性能门禁应以同机对照为准。
