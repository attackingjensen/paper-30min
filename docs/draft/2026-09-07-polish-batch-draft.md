# Windows 客户端打磨批整改草稿

> 形成日期：2026-09-07。本稿是打磨批的整改**草稿**，不是正式规格。
> 流程约定（2026-09-07 讨论）：草稿 → 作者收集多方意见 → 汇总稿交回 → 撰写正式 spec（回链 GitHub Issue）并拆 ticket。
> 2026-09-07 更新：因分析架构（方向区 C 组）可能带来功能级调整，作者决定**暂缓收集多方意见**；本稿在 C 组讨论明确前不转为正式规格与票据。新图标已选定 B。

## 背景与定位

#31 关闭后，Windows 客户端链路跑通，处于"能用"未到"好用"的阶段。本打磨批只覆盖 **UI 层**整改；解析器止血、输入保真、分析架构重组列入方向区，不在本批实施。所有改动遵守渐进式前端重设计约束：可调整布局与视觉表现，业务行为与数据契约不变。

## 主题一：静默行为修复（不丢用户的东西）

### 1. 批量生成期间提问被静默吞掉
- 场景：批量精读运行中，用户在「提问」tab 输入问题并发送。
- 现状：`sendChat` 开头 `if (!q || activeBatch) return;`（`app/ui/js/main.js:995`），输入框被清空、无任何反馈，问题原文丢失。
- 改动：批量进行中发送时保留输入内容，并明确提示原因（toast 或输入区状态）；是否允许排队待实施时定。
- 验收：批量中发送提问，问题不丢、用户知道为什么没发出去。

### 2. 技能编辑切换丢失未保存内容
- 场景：技能库中编辑提示词未保存，点击左侧另一个技能。
- 现状：`selectSkill` 直接覆盖编辑框（`app/ui/js/main.js:1512`），编辑内容无确认即蒸发。
- 改动：脏状态检测；有未保存修改时切换需确认（放弃/先保存）。
- 验收：未保存切换有确认；已保存切换无打扰。

### 3. 测试连接先落库
- 现状：「测试连接」先把表单保存再测试（`app/ui/js/main.js:1901`）。
- 改动：测试读取表单瞬时值，不写库；保存仍是显式动作。
- 验收：仅测试不保存时，设置不产生持久化变化。

## 主题二：阅读流

### 4. PDF 键盘操作
- 现状：全应用只有输入框内有键盘处理，PDF 翻页缩放只能点工具栏小图标。
- 改动：阅读视图下支持 ←/→（或 PgUp/PgDn）翻页、Ctrl+滚轮缩放；文本输入框聚焦时不劫持按键。
- 验收：键盘可翻页缩放；输入行为不受影响。

### 5. 缩放时滚动位置丢失
- 现状：`renderPdfPage` 末尾总是 `scrollTo({top:0})`（`app/ui/js/main.js:1167`），缩放和重渲染也一并回页首。
- 改动：翻页保持回页首（常规阅读器行为）；缩放/重渲染保持当前滚动位置。
- 验收：放大阅读时缩放不丢滚动位置；翻页仍回页首。

### 6. 节卡片联动 PDF：人工确认 + 定位感
- 现状：`syncPdfToSection` 只跳页（`app/ui/js/main.js:1199`）；该联动自接入起缺一次人工点击确认（未收口项）。
- 改动：完成人工确认；评估跳页时给出"第 N 页 · 某节起始"的轻提示。
- 验收：点击节卡片头部，PDF 跳到该节起始页，行为经真实窗口走查确认。

### 7. 批量生成整体进度
- 现状：批量精读只有单卡"生成中…"和结束 toast，不知第几节/共几节。
- 改动：工具栏区域显示"第 i/N 节"与成功/失败计数。
- 验收：批量过程中整体进度可见。

### 8. 流式渲染性能
- 现状：每个 delta 都对累积全文重新 `innerHTML` 并整卡 MathJax 重排（`app/ui/js/main.js:91`、`app/ui/js/markdown.js:133`），长文生成后期为平方级开销。
- 改动：流式期间轻量渲染（纯文本 + 光标），完成后做一次完整 Markdown/MathJax 排版。
- 验收：长文（≥1 万字）生成过程不卡顿，结束后排版完整。

## 主题三：任务中心与导航

### 9. 切换视图 ≠ 关闭论文（并入 Issue #33）
- 现状：任务中心与阅读页之间没有安全往返；「书库」/「← 书库」/品牌点击都会触发 `closePaper` 取消任务（详见 #33）。
- 改动：任务中心提供返回当前论文的入口；视图切换不取消任务；只有显式关闭论文才执行取消语义。
- 验收：按 #33 的四条验收标准执行，实施后关闭该 Issue。

### 10. 任务行人类可读摘要
- 现状：任务行只显示类型 + 原始 taskId（`app/ui/js/main.js:1698`），看不出是哪篇论文的什么事。
- 改动：显示论文标题（截断）+ 章节/动作摘要 + 类型；taskId 降级为次要信息。
- 验收：任务列表无需点开即可读懂每条任务的对象与内容。

## 主题四：品牌（Paper30Min 改名 + 新图标）

### 11. 改名 Paper30Min
- 范围：窗口标题（书库/任务中心显示 "Paper30Min"；阅读页显示 "论文标题 · Paper30Min"，合并原打磨项 17）、顶栏品牌（新图标 + 文字）、favicon、`tauri.conf.json` 的 `productName`（Paper30min → Paper30Min）与窗口 title。
- 文档层（2026-09-07 确认）：README、CONTEXT.md 标题及 docs 内产品称谓统一为 Paper30Min；领域术语（精读部分/精读结果等）保持不变。
- 验收：应用与文档中无"论文精读"产品名残留（领域术语除外）。

### 12. 新图标
- 现状：Tauri 脚手架默认占位图（橙底白块）。
- 方向：圆角方底、靛蓝系（与 UI 主色 #4f5de0 一致）、文档/阅读意象、琥珀色点缀。
- 候选（见 `icon-candidates/` 下 PNG，源文件为同目录 SVG）：
  - A「精读重点行」：文档中一行琥珀高亮，取"精读划重点"之意；
  - B「30 分钟进度环」：文档 + 右下角进度环徽章，取 "30min 读完"之意；
  - C「书与书签」：翻开的书 + 琥珀书签，取"持续阅读"之意。
- **已选定（2026-09-07）：B「30 分钟进度环」**。
- 实施时：以 B 的 SVG 为源替换 `app/src-tauri/icons/` 全套（32x32、128x128、128x128@2x、icon.png、icon.ico），favicon 用同款 SVG。
- 验收：窗口、任务栏与安装包图标统一；小尺寸（32px）下仍可辨认。

## 主题五：视觉系统重整（2026-09-07 真实窗口走查新增）

走查覆盖：书库、阅读（AI 精读、回想卡片）、任务中心空态、设置弹窗；样本为 SampleNet 示例论文。

### 13. 图标体系四套并存
- 现状：emoji（📚✨💬▣🔥）、汉字图标（译）、字符符号（‹ › − ＋ ⇹ ⬇ ×）、Tauri 占位图混用，风格互不相关。
- 改动：统一为与新品牌图标同族的线性 SVG 图标集；语义不明的符号（如 ⇹ 适配宽度）换为可识别图形。

### 14. 注意力层级
- 现状：顶栏打卡徽章比主导航更抢眼；每张精读卡头部都是蓝色"重新生成"主按钮，真正的主操作被淹没；书库五个操作按钮平铺无分组。
- 改动：一屏一个主操作；卡片次级操作降级（ghost/small）；书库操作分组（主导入 / 次级迁移导出）；打卡徽章弱化。

### 15. 色彩与层级单薄
- 现状：单一靛蓝 + 冷灰底，卡片层级全靠 1px 灰线；状态色（成功/警告/危险）只用于小徽标，未形成系统。
- 改动：建立色板与表面层级规范（底色/卡片/边框/阴影），状态色语义化；可探索阅读区"纸感"（暖底）方向。

### 16. 密度失衡与细节粗糙
- 现状：书库与任务中心空态大片空白、无引导；精读卡内部偏挤；设置弹窗 Temperature/字数上限行被挤压换行；PDF 页码框与工具图标偏小。
- 改动：间距 scale 规范；空态设计（插画或引导动作）；表单对齐修复；控件最小尺寸规范。
- 验收（主题五整体）：三视图应用新视觉规范，真实窗口走查确认观感；业务行为与数据契约不变。
