# Paper30Min：文本中心的论文阅读与 Agent 工作台

> 日期：2026-11-14  
> 状态：产品方向与关键政策已确认，可以进入 capability map 与分模块 spec。

## Problem Statement

**我们如何帮助以 arXiv 为主要来源、阅读计算机等理工科论文并需要中文辅助与 Agent 深问的个人读者，直接围绕可靠全文完成阅读和知识沉淀，而不必先拥有 PDF、完成 OCR 或接受逐页 LLM 审阅？**

## Recommended Direction

将权威阅读对象从 PDF 改为**带稳定文本锚点的规范文档树**。arXiv HTML 是首选来源；PDF 只是可选来源、原页对照视图或导出材料。图片、公式、表格和交叉引用随正文进入统一结构，Agent 读取同一文档的文本投影，不再维护另一份“Agent 专用解析稿”。

保留当前 v2 的 Electron、React/TypeScript、普通文件工程、Pi 会话、右侧 Agent、现有 UI 与基础设施，在其基础上重建导入、正文、批注、翻译与中栏布局，不再沿用此前“全量重写、完整移植 textfold”的设想。中栏采用**两个独立页签组**，任意中栏页面都能左右并排；结构化原文与 PDF 的双向同步只是特定组合上的增强。

右侧交互和通用会话机制可以保留，但完整审阅门禁、旧引用工具、系统提示词和成果发布逻辑必须随阅读核改变。当前地图与精解耦合的生成发布流程需要拆开，而不只是删除地图按钮。旧工程文件夹的数据兼容策略与代码基座保留是两个问题，在后续 spec 盘点中单独处理。

## Key Assumptions to Validate

- [ ] **目标论文的 arXiv HTML 覆盖率和结构保真度足够高。** 用公式、表格、图片、附录较多的代表论文验证，不以“来自 arXiv”代替质量检查。
- [ ] **文本内生锚点足以支撑全部阅读积累。** 验证正文修正、文件改名、重新导入后，批注和 Markdown 成果链接不会静默错位。
- [ ] **Markdown 中的真实锚点链接可以直接驱动侧栏卡片。** 验证扫描成本、未保存草稿、重复链接、失效链接和文件移动行为。
- [ ] **去掉五级折叠与自动论证关系后，全文＋Agent 仍能显著提升理解效率。** 以实际完整阅读一篇论文检验，而不是只比较界面观感。
- [ ] **任意页面两栏可以控制在有限复杂度内。** 重点验证打开目标、拖拽、关闭标签、草稿、焦点和重开恢复，而不是只验证视觉布局。

## MVP Scope

### 内容与原文

- 支持 arXiv URL／ID 导入，保存明确版本和本地正文快照。
- 当前结构化全文是界面、批注、翻译和 Agent 的唯一阅读权威；PDF 默认非必需，需要对照时再取得。
- arXiv HTML 不可用时，明确回退到 PDF 云端解析，不假设 HTML 永远存在或绝对无误。
- PDF 云端解析也进入同一规范文档树，不另建 Agent 专用正文。
- 取消完整 LLM 审阅后才能使用 Agent 的门禁。

### 原文修正与版本更新

- 导入来源快照保持不变，用于追溯、对比和识别上游变化，不作为第二份阅读正文。
- 用户或 Agent 可在明确任务中修正当前结构化正文；修正形成当前版本的新 revision，不伪装成上游原始内容。
- arXiv 导入固定实际版本；论文、工程、会话和成果在更新与重解析时保持同一身份。
- 用户主动检查更新。arXiv 新版本和 PDF 重解析先形成候选，确认后才切换，不自动覆盖当前正文。
- 更新时对比来源基线、本地当前版与新候选，尽量延续未变内容和本地修正；冲突逐项确认，不静默丢弃修改。
- 未变或可靠移动的内容延续原锚点；删除或无法确认的内容标记失效并保留原摘录，不根据相似度静默重挂。
- 翻译和成果是否过期按实际正文版本与锚点变化判断，不因任何更新就全部作废。

### 阅读、批注与渐进翻译

- 只做 Full 全文阅读，不做任何摘要层级。
- 高亮和批注锚定结构化正文，不再以 PDF 坐标字典为权威。
- 支持中英全文翻译和语言切换；译文继承原文结构与锚点。
- 原文结构化完成后立即可读，不等待翻译或其他派生内容。
- 翻译按章节或适当单元渐进生成，已完成部分立即可读；单段失败不阻塞其余部分，可后续补译。
- 原文版本变化后，旧译文应可识别为过期，而不是静默冒充最新译文。
- 后续版本的派生内容同样不得阻塞原文阅读。

### Agent 与成果

- 选区“解释／提问”进入右侧持续对话，不自动生成独立问答卡。
- 用户明确要求保存时，Agent 生成普通 Markdown 笔记、论文精解或记忆卡片。
- Markdown 中的文本锚点链接在对应正文旁形成跳转卡片，不另建成果关系数据库。
- 不再生成阅读地图；论文精解成为独立成果，不再附带地图发布流程。
- 不再提供以跳转到 PDF 为目的的旧引用链接体系。

### PDF 解析质量与 Agent 补查

- 质量信息由来源事实、机器导入诊断和实际核验范围组成，不合并成主观质量分数或正确率承诺。
- 来源事实记录 PDF、云端服务与模型、解析批次及本地修正；诊断只陈述已检查项目，不把检查通过等同于内容无误。
- 用户可在对照后标记章节或范围已核验；Agent 只有在明确核验任务中实际读取对应来源后才能记录核验。
- 正文后续被修改的范围自动标为“修改后未复核”，文档级摘要由实际范围记录聚合。
- Agent 始终可以解释、总结和讨论未核验正文，不必在每条回复附带笼统警告。
- 逐字引用、公式、数字或声称已对照原文等精确任务必须补查对应来源；无法补查时明确说明限制。

### 中栏工作区

- 最多左右两个窗格，每个窗格拥有独立标签条、活动页面、滚动位置和编辑状态。
- 任意中栏页面均可分栏：原文｜PDF、原文｜笔记、精解｜笔记、笔记｜笔记等。
- 普通打开进入当前窗格；「侧边打开」进入或创建另一窗格。
- 支持拖拽标签进行分栏、窗格内重排和跨窗格移动，不扩展为自由多栏网格。
- 笔记／精解卡片提供“默认侧边打开”偏好，同时保留当前窗格和侧边打开两种入口。
- 右侧 Agent 独立于中栏双窗格，并可收起。
- 只有结构化原文与 PDF 等兼容组合才提供语义同步定位。

## 成功标准

- 导入一篇受支持的 arXiv 论文后，不下载 PDF、不配置模型，也能离线重开并阅读完整结构化正文。
- 原文结构化完成后无需等待派生任务；翻译逐段出现，已经生成的部分可以立即阅读。
- 原文与中／英译文可以切换，批注和成果链接仍指向同一原文位置。
- 选区提问不会制造问答卡；保存为 Markdown 后，正文旁出现可回跳的成果卡片。
- 任意两个中栏页面可以并排打开，拖拽调整标签后保留各自草稿与阅读状态，重开后布局可恢复。
- 原文修正后仍可追溯来源快照；采用新候选时，本地修正与可靠锚点按确认结果延续，冲突和失效均有明确呈现。
- PDF 解析稿未经完整 LLM 审阅也能阅读和交给 Agent，来源、导入诊断与实际核验范围清晰可见。
- Agent 对未核验正文进行精确引用或声称已对照原文时，必须补查来源或明确说明无法完成核验。

## Not Doing (and Why)

- **五级折叠及逐词缩放动效** —— 当前只需要全文，避免重新引入整套生成与对齐管线。
- **自动论证关系** —— 推迟到后续版本，不为截图中的观感增加一条模型生成和质量验证链路。
- **阅读地图** —— 新方向保留论文精解与笔记，不再维持第三类全文导航成果。
- **独立选区问答卡** —— 临时提问属于对话，只有明确保存的 Markdown 才成为成果。
- **本地 MinerU** —— 安装与运行成本不符合产品约束，PDF 继续使用云端解析。
- **完整移植、全量重写或追随 textfold 版本** —— 旧设想作废，只吸收已确认的机制与观感，并保留当前 v2 代码基座。
- **自由多栏／上下网格停靠** —— 当前只做任意页面两栏及标签拖拽，避免把阅读器变成通用 IDE 布局框架。
- **中英以外的论文翻译** —— 先验证中英阅读链路，不建设多语言产品体系。

## 交付边界

以下是已确认的方向，不代表本轮已经执行：

1. 先完成产品与方向对齐，并将现行契约重写为 `docs/spec/` 下的多份规范。
2. 规格完成后删除旧 v1 源码。
3. 收尾并合并当前 `codex/v2.0.0` 分支到 `main`。
4. 后续从最新 `main` 创建短分支，按阶段或任务提交小 PR。
