Grounding Context

Codebase Context。产品目标是让个人读者能复述一篇论文的「问题、方法、证据、边界」。现有 Windows 客户端已有阅读地图、节摘要、按需深挖、复述稿、原文出处跳转、问答和回想卡。v1.1.0 的主要变化是缩短等待：3 篇论文的同机对照中，全链耗时约为旧版的 1/8，提速 8.0–8.4 倍。这些样本不能证明「30 分钟读完」，也没有验证理解质量。
8.0–8.4×v1.1.0 全链同机对照提速；仅 3 篇样本
5 条独立取证维度，覆盖阅读与交付
6 / 13合并后的候选中保留 6 个方向
  • 定位：Windows 本地书库是论文内容权威来源。产品围绕单篇论文精读，由 1 人开发维护；Android 首版只做已选论文的阅读伴侣。来源：STRATEGY.md、CONCEPTS.md。
  • 理解缺口：复述稿由模型生成；回想卡可手写，也可由 AI 起草并覆盖现有正文。当前没有统一的理解质量采集或评分。来源：main.js:1619、STRATEGY.md:39。
  • 证据缺口：出处指针目前主要核验页、图表或文本块地址存在，尚不能判断引用是否真的支持句子的意思。来源：protocol.js:432。
  • 可靠性缺口：「导出整库」只显式打包 PDF；当前迁入面向旧浏览器书库，按论文 ID 跳过既有记录，也只创建 PDF 附件。现有路径不能证明 Windows 书库完整恢复。来源：papers.js:384、migration.rs:727。
  • 既定方向：云同步与 Android 的 #25、#26 仍未启动。升级、干净安装、卸载及安装版侧车检查亦未完成。来源：current.md。

外部竞品调研未完成：本次环境没有可用的专用网页搜索和抓取工具。下文「价值」与置信度是基于项目目标、现状和实现差距的判断，不是用户偏好、准确率或市场需求的实测结果。

1.用户自主复述与证据对照

理解闭环置信度 82%复杂度 中
描述
读者自愿写下「问题、方法、证据、边界」的简短解释，再与现有 AI 复述稿和原文出处对照。系统指出遗漏、冲突和缺少证据的地方，保存读者修订前后的说法；不把 AI 草稿或「已读完」标记当作理解成绩。
轴
从阅读到复述的理解闭环
依据
direct: STRATEGY.md:18、39 把「能讲清」作为目标，同时承认没有采集机制；papers.js:202 的回想卡只有当前正文、图片和更新时间。reasoned:读者自己先说明白，才有可观察的理解差距；模型代写的稿件不能替代这个信号。
价值
让产品第一次直接服务于「用户本人能否复述」，而不只是产出一篇看似完整的讲解。它复用现有回想卡、复述稿和出处跳转。
代价
需要避免强制向导和伪精确分数；模型指出的差异也必须允许读者回查、否定。真实用户是否愿意主动写一段复述，尚未验证。
读者自己的解释→AI 稿与原文对照→缺口回访→读者修订

2.关键论断的证据质询

证据质量置信度 85%复杂度 高
描述
针对地图、深挖和复述稿中最重要的论断，让读者并排查看引用的文本块或图表，标记「支持、部分支持、冲突」。遇到「方法为何有效」的主张，再明确它对应的实验、比较基线和论文承认的限制；没有这类实验的论文不强套模板。
轴
原文与证据可信度
依据
direct: protocol.js:432–483 只检查出处地址有效；STRATEGY.md:12、41 要求把方法和实验依据联系起来，却尚无准确率指标。reasoned:合法出处可能只沾边，不能证明句子没有夸大结果。
价值
把「有引文」推进到「读者知道这条引文能证明什么」。它与方向 1 互补：自主复述暴露缺口，证据质询帮助填补缺口。
代价
自动判断语义支持容易再次引入模型错误；应先聚焦少量关键论断与人工核对。逐条建立论断和图表关系的成本较高。

3.可验证的整库恢复

书库可靠性置信度 95%复杂度 中
描述
让「导出整库」对应一条真正能恢复的路径：备份论文记录、阅读位置、PDF、页图、裁切图和回想卡图片等被引用的附件，并附完整性清单。在干净账户恢复后核对记录和哈希；旧浏览器书库迁入保留独立语义。
轴
本地书库与交付可靠性
依据
direct: papers.js:384–426 的导出只显式收 PDF；migration.rs:727–771、985–1050 只为新增 ID 创建 PDF 附件；STRATEGY.md:29 指定本地书库为内容权威来源。
价值
保护用户累积的唯一权威内容，也为未来移动副本和版本升级提供可验证的退路。这是当前按钮文案应兑现的能力，适合按风险尽快交付，不必等待 v2.0.0。
代价
需要明确现有同 ID 记录、设置和 API Key 的恢复语义；大附件使备份体积与恢复时间增加。现有代码判断仍需完整恢复演练确认。

4.精选论文的 Android 接续

跨设备置信度 75%复杂度 高
描述
Windows 只发布用户主动选定的论文，手机读取完整、不可变的原文与阅读产物副本；离线时继续读旧的完整版本，回网后同步阅读位置。Android 不导入、编辑或生成论文，也不接收模型密钥。这一方向延续现有 #25 和 #26，不是新发现。
轴
跨设备接续阅读
依据
direct: STRATEGY.md:29–33 确定 Windows 权威源和 Android 阅读伴侣；#25/#26 明确选定论文、完整版本、离线缓存与旧位置不回退。reasoned:先用单篇论文的真机离线接续验证价值，可避免在需求未证实时承担完整服务运维。
价值
满足已经确认的跨设备继续阅读需求；如果实际使用频繁，它可以独立成为 v2 的主线。
代价
涉及同步服务、账号、版本原子性、移动缓存和两类真机验证，单人维护成本高。它可能占据整个大版本的开发容量。

版本取舍：若优先实现 Android，宜把它视为与「自主复述 + 证据核对」竞争资源的主线，而非默认同时承诺两套完整能力。

5.带未解问题的续读

阅读连续性置信度 76%复杂度 中
描述
读者把「我还没弄懂什么」留在某个原文块、图表或节上。下次打开论文，先回到这个问题和证据现场；补读后写下自己的解释并关闭它。精确到块的阅读断点是这个体验的支撑，而非单独追求滚动位置像素级还原。
轴
阅读交互与连续性
依据
direct: papers.js:221–227 的问答只保留最近 40 条；view.js:259–272 的位置只存视图、节和 PDF 页；synthesize.md:12 已有「未经深挖核验」标记。reasoned:阅读中断后，找回尚未回答的问题通常比只找回页码更接近继续思考。
价值
把瞬时问答和未核验标记变成可积累、可完成的个人理解线索，同时直接服务每天继续读同一篇论文。
代价
需要避免演变成通用任务清单；问题的来源锚点遇到原文修订时要有降级规则。真实使用频率尚待观察。

6.原文校勘与产物复核

证据质量置信度 81%复杂度 高
描述
允许读者修正解析后的原文块，同时保留 PDF 原貌、机器抽取文字和人工修订版。与该块有关的摘要、深挖、翻译和复述稿显示「需重新核对」；图表与公式仍能回到原始 PDF。先以单块修订及保守提示为边界，不预设完整依赖图。
轴
原文与证据可信度
依据
direct: current.md:11 已列「编辑原文入口」；pdfmap.rs:88–109 的块号、页码和图表位置承载引用地址；CONCEPTS.md:16 禁止把推测当作已提取事实。
价值
修复原文抽取错误时不悄悄改写证据，降低错误沿 L2、深挖和复述稿传播的风险。
代价
文本块身份、重解析与历史出处的关系难处理；如果不控制范围，会变成庞大的版本管理系统。编辑入口本身已属现有待办，新增价值在可追溯和失效提示。

Rejection Summary

六组视角产生约 48 条原始提议；合并重复表达后得到 13 个候选，保留上面 6 个。下表记录另外 7 个的去向。

候选筛选结论
通用「方法—实验」图谱与方向 2 合并。不是所有论文都有同形的对照、实验或消融；先核对重要论断。
只改进页内滚动位置与方向 5 合并。精确位置有用，但单独不足以成为 v2 方向。
单篇移动离线试验纳入方向 4 的判断依据，不作为发布功能；#26 已要求先用伪服务和确定性材料验证。
任务中断后自动续跑进程内任务记录消失的问题属实；不同解析和模型任务的安全续跑边界不同。先把持久终态和重试语义作为可靠性工作。
安装版升级、干净账户、卸载走查必须完成的发布验证，current.md 已明确列出；不是新的 v2 产品方向。
PDF 按字节范围读取已列待办；先测大 PDF 打开时间和内存，再判断实现投入。它不改变产品核心价值。
代表论文的质量哨兵可作为解析与出处的回归门槛；与现有夹具和发布验证相邻，不单列为用户方向。

独立核对指出：方向 1 不应变成强制先写的向导；方向 4 与现有规格高度重合；方向 3 的恢复缺口需用真实书库演练确认。这些限制已计入排序和代价。
